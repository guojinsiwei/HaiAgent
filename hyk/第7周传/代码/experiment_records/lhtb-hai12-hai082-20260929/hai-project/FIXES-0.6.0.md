# HAI 0.6.0：轻量滚动子目标

## 为什么没有加入完整 Planner

- Magentic-One 在开始时生成 Task Ledger，并在每轮额外生成 Progress Ledger；连续停滞后再规划。能力完整，但会增加模型调用、结构化输出失败面和管理开销。
- TaskWeaver 同时维护 `init_plan`、压缩后的 `plan` 和 `current_plan_step`，其官方说明也明确省略了一部分 Planner CoT 以控制提示长度和推理开销。
- SWE-agent 一类强基线仍以模型动作—环境反馈主循环为核心，并不要求独立子目标规划器。

因此 HAI 只吸收最小共同部分：当前焦点可持续可见。

## 实现边界

- HAI 的 run 动作新增短 `subgoal`；与 `strategy` 分离。
- 没有额外模型、额外请求或隐藏的任务成功判断。
- 运行时自动记录最近 6 个子目标的尝试、策略、结果、工作区变化和证据。
- 切换仅表示旧目标暂时挂起，不表示完成；退出码 0 和工作区变化也不表示完成。
- 精确重复时同时标记当前策略和子目标停滞，但优先提示在同一子目标内换策略，只有焦点真正受阻才换子目标。
- 旧 provider 若漏掉字段会使用 `purpose` 或任务级占位回退，并在审计日志写明 provenance；不会伪称模型主动规划。
- Raw 协议、提示和运行行为不变。
