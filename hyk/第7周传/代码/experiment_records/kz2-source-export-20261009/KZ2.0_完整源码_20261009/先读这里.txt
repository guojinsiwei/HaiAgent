一、先看这些文件

1. runner.py
   实验真正的解题入口：创建模型客户端、工具环境、共享预算和运行开关。
   实际调用 RoutedTaskRunner；不是 best_first_runtime 的图搜索入口。

2. sources/bestfgs-project/src/bestfgs/lean_runtime.py
   基本主循环：读上下文 → 请求动作 → 检查 → 执行工具 → 记录证据/记忆。

3. sources/bestfgs-project/src/bestfgs/error_routing.py
   在基本循环上增加 1/3/4/2 四种处理：
   1 格式、参数或语法错误，保持目标做局部修正；
   3 保守识别的只读侦查动作免做正交证明，但仍受重复检查；
   4 提交前由 Critic 提出公开检查，执行后根据真实结果复核；
   2 子目标检查通过后保存文件，固定检查退化时有限回溯。

4. sources/bestfgs-project/src/bestfgs/subgoals.py
   子目标定义、依赖、验收命令和证据状态。
   文件变化会使旧验收失效；局部检查通过不等于官方任务通过。

5. sources/bestfgs-project/src/bestfgs/contrastive_exploration.py
   负面锚点与正交校验。相关代码/依赖确实改变后，同一测试允许重跑。

6. sources/bestfgs-project/src/bestfgs/lean_memory.py
   sources/bestfgs-project/src/bestfgs/memory_injection.py
   单题记忆的保存、检索及决策前注入。

7. sources/bestfgs-project/src/bestfgs/action_loop.py
   sources/bestfgs-project/src/bestfgs/rejection_recovery.py
   最终动作排重与恢复建议。拒绝次数不再直接结束整题。
   仍保留重复拦截，仍可能耗尽请求预算，不是保证脱困的机制。

二、与之前的 DH v9 有什么区别

对照对象明确为 2026-10-04 的冻结 DH：recovery-counter-fix-v9，
不是 Solver/Planner 的图搜索版，也不是后来不断变化的工作目录。

共同点：单题记忆、Monitor、Advisor、正交探索；同一模型承担各角色。
两者都没有开启图搜索、两候选预测或跨题记忆。

主要新增：
- 独立子目标机制，绑定公开验收命令和实际证据。
- 四类问题分别处理，不再把格式错误、缺信息都当作必须换方向。
- 提交前新增 Critic 检查角色，但其认可不代表官方正确。
- 子目标通过后的文件检查点，以及有限文件回溯。
- 排重更看相关依赖是否改变，而不只看整个工作区；实际修复后允许重测。

KZ2.0 的后续工程修补（不要误说成旧 v9 原本全有这些问题）：
- 删除派生版中的“恢复拒绝达到上限就结束整题”。
- 记忆分析文字长度改成建议，不再仅因超长拒绝有效动作。
- 工具命令时间窗由 Harness 控制；这份修订为 600 秒，模型填 60 秒
  不再直接把长命令掐掉。每题总墙钟仍是 7200 秒。

配置区别需要单独看：
原 v9 小预算参考：48000 字符上下文、动作输出4096 tokens，800逻辑请求。
这份 KZ2.0：1M上下文 allowance、输出32768 tokens，所有角色与重试
共同使用800次实际API尝试、600次工具；保留单题50元保守费用保护。
这是资源/计数配置变化，不能当作算法提升；与大预算v9比较时须另核对配置。

三、这个副本的边界

所有解题源码、历史模块、测试、兼容层和部署 Python 代码都保留了。
src 里出现 best_first、route_selection 等历史文件，不代表当前实验启用了它们。
协议里还有13/134的备用开关，但本轮 methods 是1342，四种路由均开启。
protocol.json 的任务列表只有 cow：它记录的是最新一次补跑，并非全20题配置。
不要把先前“19题合并均分”称为这份修订统一跑出的成绩。

此副本用于读代码。没有打包官方题目、测试数据、Docker镜像及Python依赖环境；
原部署脚本中仍有学院服务器绝对路径。不要直接运行 launch/prepare/评分脚本。

EXPORT-MANIFEST.json：172个原始文件的SHA-256和来源。
V9-COMPARISON.json：冻结v9的逐模块比较及两边配置，方便追溯。
source-provenance.json / historic-config-lock.json：原实验的版本血缘与哈希。
