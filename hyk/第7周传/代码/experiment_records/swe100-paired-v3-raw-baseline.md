## 核心结果

- 固定题单 100 题，100 个不同任务；每题一次方法运行，无整题重跑（不代表没有请求级重试）；100 题指标轨迹完整。
- 官方工具评测成功率：**79/100 = 79%**。非空补丁未通过 19 题，空补丁 2 题，评测基础设施错误 0 题；空补丁计入失败分母。
- 平均交互轮次：**14.14 轮/题**（总计 1,414 轮）。
- 工具调用冗余率：**2.8836%**（109 / 3,780，所有任务汇总后的微平均，不是逐题比例的平均）。
- 工具调用：3,780 次，平均 **37.80 次/题**。
- 平均方法运行耗时：约 **16.47 分钟/题**，不含之后的官方评测；受服务器、网络和计数开销影响，不等同于模型推理时间。
- 已记录输入 token：29,371,323；输出 token：13,197,219。中断请求可能缺少 usage；不是账单，也不能单凭总 token 推算费用。

## 固定条件与指标口径

- 数据：`SWE-bench/SWE-bench_Verified`，`test` split 中本实验固定的 100 题；不是全量 Verified 成绩。完整题单和逐题环境哈希见原始报告 `comparison.protocol`。
- “裸模型”指 `raw` CLI 交互基线：仍有执行工具、任务上下文与通用接口处理，并非单次无工具问答；冻结实现位于 `releases/interface-hardening-v5/src/bestfgs/raw_baseline.py`。
- 官方 DeepSeek API，请求模型及响应模型均为 `deepseek-flash`；temperature=0.2，reasoning/solve reasoning effort=high。记录的响应 fingerprint：`aeb56401ca74e127821c4f9126dcb669`。
- 每题主动作轮次上限 24，CLI 调用上限 80，每动作最多 4 条命令，任务时限 14,400 秒；自适应预算关闭，独立 LLM 成功裁判关闭。两方法的动作/工具预算一致，**不是等 token 预算**。
- 指标版本 `cli-comparison-v1`：使用 `comparison_metrics`。一轮是实际发生 CLI 调用的执行批次，不是一次 API 请求；独立最终验证也纳入统一口径，动作内嵌验证归入该动作轮次。平均值覆盖全部 100 题，不只计算成功题。
- 冗余判定：相同归一化命令、相同执行前工作区指纹、相同返回结果曾经出现，且调用前后工作区未变。这是严格重复调用代理指标，**不是所有语义冗余的比例**，也不保证每次重复都无必要。
- 成功只取官方 harness 的 resolved，不使用智能体自己的成功标记。评测时限 1,800 秒/题；SWE-bench 4.1.0；harness commit：`f7bbbb2ccdf479001d6467c9e34af59e44a840f9`（干净工作区）；Docker 29.6.2。本地运行官方评测工具，不代表已提交官方排行榜。

## 后续是否需要重跑

**可以作为固定历史基线复用，不必每次修改 BestFGS 就重跑裸模型。** 前提是题单、任务起始状态/依赖环境、基线实现与提示词、模型及采样设置、共同预算、工具接口和评测规则保持可比。新 Agent 版本应另立记录，不冒用旧协议哈希。

换题、改变共同预算/环境/接口，或 API 模型版本发生变化时，不能直接把本结果当作同条件对照；应补跑受影响基线。只修改评测器时，优先用已保存补丁重新评测两组；只修改统计口径时，优先从双方原始轨迹重算，不必重新调用模型。延迟或价格比较也需考虑时段、硬件和价格变化。

本结果是一次随机生成运行，不是多次重复的均值。正式研究若要估计生成波动，应为两方法设置一致的重复实验方案；不能只挑新方法的最好一次。若依据这 100 题反复调试，它们应作为开发集，最终结论另用未参与调试的保留题验证；新题也需要相应裸模型基线。
