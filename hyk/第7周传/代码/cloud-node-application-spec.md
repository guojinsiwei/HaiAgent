## 三、最低可接受配置

若资源预算有限，可降为：8 vCPU、32 GiB 内存、500 GiB ESSD、5 Mbps 公网带宽。低于该配置时，多容器并发、软件依赖编译和大型测试套件容易相互争抢 CPU、内存和磁盘 I/O，实验耗时与失败率会明显增加。

## 四、申请理由

本课题研究面向复杂 CLI 场景的软件工程智能体，需要在隔离环境中重复执行代码检索、依赖构建、补丁生成、编译和自动化测试。单个实验通常包含多轮模型交互和多次工具调用，并需同时运行实验方法与裸模型基线，以保证相同题目、相同模型、相同预算下的配对比较公平性。

现有 4 vCPU、16 GiB 节点只能承担低并发预实验。开展 30–100 道任务的中等规模对照实验时，任务环境、源码工作区、依赖缓存、日志和结果快照会持续占用磁盘；多个容器并行还会产生明显的 CPU、内存及随机 I/O 竞争。因此建议配置 16 vCPU、64 GiB 内存和 1 TiB ESSD，使节点能够稳定并行运行 3–4 个任务容器，并保留失败复现、指标审计和后续消融实验所需的完整产物。

该节点不承担大模型本地训练或推理，因此暂不申请 GPU。相比申请 GPU 服务器，将预算集中在 CPU、内存、SSD 容量与稳定网络上，更符合本课题的实际负载，也能降低总体成本。

## 五、主要软件与用途

- Docker/OCI：为每道基准任务提供独立、可复现的运行环境。
- Python 3.9–3.11 与虚拟环境：兼容不同软件仓库及实验框架。
- Git：固定代码版本、生成补丁并保存实验快照。
- SSH 与 tmux/systemd：远程部署、断线续跑与进程守护。
- SWE-bench / Terminal-Bench 评测工具：执行软件修复与 CLI 长程任务。
- 日志、心跳与恢复脚本：监控长期实验，处理可恢复的网络故障。
- 大模型 API：完成智能体决策；API 费用与云服务器费用分开核算。
