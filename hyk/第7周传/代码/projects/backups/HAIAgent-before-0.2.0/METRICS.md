# HAIAgent 测量协议 v1

目标是测到任务解决效果与交互成本，而不是奖励短轨迹或制造好看的低冗余值。指标只在执行器边界和离线分析阶段记录，不作为在线评分、分支选择或提交判定。

课题文档提出成功率提升 10%以上、平均交互轮次降低 30%以上、工具调用冗余率降低 50%以上，但没有给出三个指标完整操作定义。下列是本工程明确冻结的新协议，不与 v14 或历史 100 题的旧指标直接混算。

## 成功率

`success_rate = 独立评测通过的题数 / 固定计划题数 N`。

一次模型 `submit` 只表示提交，`success` 仍为未知。空补丁拒绝、超时、API 异常、未提交等停止原因单独保存；不得为了提高通过率把失败题从计划题单删除。基础设施故障要报告并按预先约定的重试协议处置，不可仅选择某方法效果更好的尝试。

全部题目独立判定完成才输出完整 `success_rate`。部分评测时返回：

- 下界：已确认通过 / N。
- 上界：（已确认通过 + 尚未独立判定）/ N。
- 已运行、已评测、缺失题目数量和题号。

`attach-evaluation` 绑定 run ID、task ID、artifact SHA256、真实原始报告路径与 SHA256；`independent=true` 是受信导入者的声明，不是自动证明。只允许导入实际 verifier 的结论，不能导入策略模型的“我觉得成功”。

## 平均交互轮次

每收到一次策略模型响应，计一个 `interaction_round`，包括：

- 执行动作决策。
- 提交决策（包括被拒绝的提交）。
- 不完整输出和格式错误响应。
- 因工具预算已用尽而未执行的行动决策。

纯网络重试或提供方未返回有效响应信封不增加策略交互轮次，但全部算 API 请求，并另报时间、usage 与未知费用覆盖。这版每轮最多一个执行器调用，不通过一轮塞入很多命令来降低轮数。`bash -lc 'a; b'` 仍是一条执行器调用，子命令并非独立计数单位；必须在对比中保持相同工具契约。

`average_interaction_rounds = Σ 每题交互轮次 / N`，主值覆盖全部固定题目，包括失败题。题目未运行时不能直接当作 0 轮；主值保持未知，同时提供已完成运行均值。

附加记录 `tool_feedback_rounds`、API 请求数、格式错误数、墙钟时长和 token 统计。额外提供成功题均值和两组共同成功题均值，但不替代全题均值。更早失败也可能产生更少轮次，所以必须与成功率一起解释。

## 工具调用冗余率

计数单位是 Agent 分发到执行器的一次 `run` 调用，包括超时、非零退出、cwd 拒绝等调用尝试；`submit`、补丁导出、文件指纹扫描、上下文组装不算 Agent 工具调用，相关成本仍包含在墙钟时长。审计不把调用失败本身判成冗余。

定义：在**该调用发生之前模型实际可见的信息、相关状态和任务需求**下，该调用可以避免，且并非获得新信息、改变任务状态或履行合理验证义务所必需。

主要类别：

| 类别 | 允许判冗余的依据 | 不应判冗余的情况 |
|---|---|---|
| equivalent_information | 已有可见且仍有效的同一事实，换命令重查没有新信息 | 前次只看到截断片段，或者这次扩大了检查范围 |
| known_unchanged_blocker | 明确阻塞仍在、相关条件未变，重试目标操作没有合理新信息 | 条件改变、服务恢复、随机/网络不稳定需确认 |
| unnecessary_reverification | 相同目标已有适用验证，且不存在新的合理验证义务 | 代码改变、扩大回归范围、验证偶发性或交付检查确有需要 |
| irrelevant_to_goal | 题面/约束直接支持该操作与当前任务无关 | 当时有合理诊断假设，虽然最终没解决问题 |
| other_no_increment | 审核者能明确给出额外的无增益依据 | 单凭没有修改文件、结果相同、最终失败或命令相同 |

**“机械重复”不是这里的判据，也不输出机械重复率作为主指标。** 不同命令可以冗余，相同命令也可以合理。模型的 `purpose` 只是审计线索，不是让模型给自己判分。

日志保留调用前的实际上下文/反馈，不只保留执行器捕获的更长输出。尤其不能用压缩时已删除、模型根本没看见的事实指责它重复查找。

### 审计流程

1. 运行结束后导出 `audit-template`，初始所有调用均为 `unknown`。
2. 审核者逐条检查题面、可见资料、相关状态变化、调用结果与目的，标注 `redundant / nonredundant / unknown`。
3. 已判定项填写理由和 reviewer 标识。冗余项还要填写类别、`conditions_unchanged=true` 和支持它的先前可见调用 ID。与题目明显无关的调用可用 `task_evidence` 引用题面原文作为依据。
4. 原始 command/result/visible information 等证据字段不得修改；导入后校验它们与 trace 完全相同。不能引用未来调用或当时不可见的证据。
5. 正式论文实验建议两位独立审核者或固定版本的独立离线审核流程，再解决分歧；保持两组同一规则，记录一致性和未知率。自动语言模型审核若以后加入，也必须和策略模型分开、固定协议，并用人工子样本验证，不能预先宣称其判断为真值。

模板不显示显式方法名和最终成功结果，但行为及结构化记忆特征仍可能泄露分组，不能宣称实现了完全盲法。审计工具负责证据完整性和汇总，不能机械证明审核理由的语义正确性。

### 汇总

单题已知 `R` 次冗余、`U` 次未知、总共 `C` 次调用：

- 全部完成审计才有主值 `R/C`。
- 部分审计报告区间 `[R/C, (R+U)/C]` 及覆盖率 `(C-U)/C`，不把未知当非冗余。
- `C=0` 时该题冗余率未定义，而非 0；单独报告零调用题数。
- 主实验工具冗余率采用微平均 `ΣR / ΣC`，反映总体调用成本；同时报告非零调用题的宏平均，防止长轨迹主导结果被隐藏。
- 只有全部计划题已运行且所有调用已审计，才报告完整实验主值。不存在调用结果或 trace 中断时不会假称完整。

这些规则把语义判断放到可复核的审计中，而不是用极窄的自动重复检测冒充语义冗余率。代价是需要离线审计工作；这是指标可信度与自动化之间的明确取舍。

## 配对比较与目标

同一冻结题单、同一模型/提供方与生成参数、同一工具协议、同一预算和干净初始环境。每方法每题一条预先指定的主运行，不挑最佳结果。记忆只在当前任务内存活，不在两组间共享。

`compare` 同时报成功率百分点差、相对成功率提升、相对轮次下降与相对冗余率下降；Raw 分母为 0 时相对变化未定义，不虚构无穷提升。还报告共同成功和单边成功题数，便于做配对统计。

课题中的“提升 10%”应在预注册中明确是相对提升还是增加 10 个百分点；本工程两者都输出以避免混淆。有限样本中的点估计不等于显著提升，这一版不自动生成显著性或“达到课题目标”的结论。
