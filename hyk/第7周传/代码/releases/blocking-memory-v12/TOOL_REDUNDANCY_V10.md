# 工具调用冗余率：可复用证据口径

本版本实际替换自动判定算法，不再仅改名，也不要求先完成人工标注才能得到数值。它是实验的**操作性定义**，不是对任意程序的“所有无用行为”做语义裁判。

## 1. 主指标与分母

对一道题的一次方法运行，记实际进入共同执行器的调用总数为 N，被规则确认的可避免重复调用数为 R，未能可靠分类的调用数为 U：

**工具调用冗余率 = R / N。**

一个调用计入 R，必须同时满足：

1. 本任务此前已实际执行过同一操作，或规则支持的等价读取，留下完整证据；
2. 相关文件内容、执行环境指纹等条件未变，本次执行前后条件也未变；
3. 返回码及有效输出与旧证据一致，没有新增观测；
4. 没有待完成的首次提交复验义务；
5. 调用没有工作区副作用、截断、超时、阻止或已识别的环境故障。

N 包含普通操作、功能验证、最终复验、失败、超时和被执行器阻止的调用；未实际执行的搜索候选、经验拦截、内部文件哈希、自动语法门槛不进入 N。内部测量耗时仍记入 instrumentation_seconds。N=0 时率为 null，不是 0。

跨题不复用指标缓存；同题的搜索分支共享此前返回过的观测。衡量的是同一方法在任务中重复获取已有证据，不要求当前提示词恰好仍保留该证据，也不宣称换成缓存必然保留同等成功率。

## 2. 具体判定

| 调用情况 | 处理 |
|---|---|
| 对未变化的文件反复执行同一读取/查询 | 完整输出一致时计冗余 |
| 只改了其他无关文件，再次读取原文件 | 仍可计冗余；不再用整仓库变化掩盖重复读取 |
| 相关文件变化，或读取内容/切片变化 | 新条件或新操作，不计重复 |
| 单文件 cat 与 sed -n '1,$p'，路径归一化后相同 | 支持有限等价；输出仍必须一致 |
| Python 的严格只读表达式 print(open('file').read()) 或 from pathlib import Path; print(Path('file').read_text()) | 通过白名单 AST 识别，不执行表达式进行分析；输出一致才可复用 |
| 显式 pytest 或直接执行工作区内 Python 脚本 | 采用整个可观测工作区指纹，不能只看测试文件；普通动作和验证通道使用同样规则 |
| 修复源代码后重测 | 工作区条件变化，旧证据失效，不计冗余 |
| 相同条件下首次最终复验 | 固定豁免一次；仍在 N 中 |
| 同一操作、同一条件下后续最终复验 | 没有新义务且输出一致时计冗余，不无限豁免 |
| 相同公开断言失败且条件没变，再执行同一检查 | 可计冗余；网络/导入/权限/超时等已识别故障不这样处理 |
| 截断、超时、缺失/外部依赖、递归搜索、复杂 shell、任意 Python -c | 未覆盖的情形记 unknown，不断言为非冗余 |

直接读取白名单包含 cat、head、tail、wc、有限 sed、显式普通文件的 rg。拒绝工作区外路径、符号链接/目录依赖、不支持的参数及过大的依赖文件。通用程序行为不可静态完全判定，因此不把复杂 shell 或任意脚本输出相同直接等同于“无用”。

本地 Python 探针与 pytest 的重复判定以**固定、工作区内的可复现任务环境**为适用前提。二进制、环境变量、工作区指纹不是整个操作系统或外部服务的状态证明；依赖网络、随机性、并发进程、外部文件或动态依赖的探针不适合据此宣称语义冗余。已识别到这些不确定信号会记 unknown；没有识别到不代表已证明不存在。该限制必须随实验报告保留。

只忽略已识别 pytest 结果汇总中的运行时长；测试数量、成功/失败状态及其他输出全部保留。描述文字、模型自述、语义方向、是否引用经验、最终官方成败，都不能直接决定某次调用是否冗余。

## 3. 如何公平报告

主字段为 tool_call_redundancy_rate、redundant_tool_calls。avoidable_repeat_rate 是同一新自动指标的别名。旧机械重复值单独保存在 mechanical_repeat_*，不再顶替主指标。

同时必须报告：

- N、R、U，以及分类覆盖率 (N−U)/N；unknown 不能从分母删掉。
- [R/N, (R+U)/N]：仅为本口径下未知调用的敏感性范围，不是置信区间，更不是全部语义浪费的理论界限。
- 按 action、functional_verification、final_verification 拆分的调用数、冗余数和未知数。
- 成功率与交互轮次、总调用数、模型调用/令牌/时间；不能靠增加大量非冗余调用把比例稀释后宣称更高效。

两组使用同一检测器，检测器不改变动作、不读取 Agent 的经验库、不增加模型裁判/API 调用。比较器主输出使用新 R/N，旧机械值只作诊断。总体用微平均 sum(R)/sum(N)，另报题级宏平均；相对下降为 1−rate_Agent/rate_Raw，裸模型冗余率为 0 时下降比例无定义。

两组均成功的配对题用于条件效率比较，同时保留全部完整单次运行配对题；不能只展示有利子集。覆盖率明显不同或未知占比很高时，自动下降数值只能解释为“已检测到的可复用证据冗余下降”，不能外推全部浪费下降。任务级配对 bootstrap 区间反映任务采样，不解决检测漏判、模型多种子或仓库聚类问题。

成功率仍用官方 resolved/N；交互轮次仍为共同执行器的 CLI 反馈批次。这两个定义未改。

## 4. 版本和旧结果

- 新轨迹：cli-comparison-v2；报告：cli-metrics-report-v3；判定器：reusable-evidence-v1。
- 每条新调用记录原始命令/输出摘要、相关条件摘要、分类原因和此前证据的调用 ID。不保存命令文本、输出正文或环境密钥。
- v1 轨迹仍可按旧机械口径读取，不能从仅有旧哈希的数据恢复新指标；旧实验不是“新冗余率为 0”。新旧版本拒绝混合配对。
- 新入口自动使用新检测器。旧云端冻结目录和历史结果没有修改；本地修改不代表云端已更新。无需重新做已完成的官方判分来解释旧成功率，但要获得新冗余指标需要具有新证据记录的运行。

可离线汇总新记录（不执行模型或官方评测）：

```text
python audit_tool_repetition.py report --trace <cli-metrics.jsonl> --output <new-metrics.json>
```

人工审计入口保留作抽查和扩展误差评估，不再是输出自动主指标的前置条件。
