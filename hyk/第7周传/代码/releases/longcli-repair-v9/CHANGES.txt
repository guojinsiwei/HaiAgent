Implemented changes
1. Exported solver roots receive real null/zero/random/urandom character devices.
   /dev/null is required to have major/minor 1:3 and mode 0666. Every command
   launcher checks it. Preparation checks EOF/discard behavior and clean stderr.
   The fix is in common environment preparation, so future v6/RAW comparisons
   must use it as well. chmod on a regular file is deliberately insufficient.
2. Contrastive rejections return recoverable feedback and do not increment the
   protocol-error counter. Two consecutive rejections execute one counted,
   read-only diagnostic, close the exploration episode, and return to normal
   decisions. Model requests, tools, and wall budgets are still enforced.
3. Orthogonal planning now proposes two short executable hypotheses with literal
   supports/refutes markers, selects one, and executes only that candidate.
   Follow-up requires one candidate. The selected action must match argv/cwd/stdin.
   This is a bounded forecast inside the existing actor request, not HAI routing,
   a new model, tree search, or extra candidate execution.
4. The final dispatch checks normalized command identity and current workspace
   state against up to 48 prior unchanged observations. Repeated commands get a
   cached result without consuming a tool call. Source edits change the state
   and allow rechecking. An external state claim allows one explicit loop_retry.
   Normalization preserves quoted data, stdin, cwd, expansion and heredoc syntax.
5. Repeating a failed check after an observed relevant dependency repair is
   permitted by the contrastive gate. Unrelated file changes do not clear it.
6. contrastive_outcome records prediction, unseen observation, workspace change,
   and improvement of the same explicit public pytest check. Proposal acceptance
   is not called success. Both/no prediction markers, incomplete captures, timeouts,
   and blocked commands remain unknown. Public checks are not official task scores.
