## 收录范围

当前源码、冻结基线、探索改进版、BestFGS/HAIAgent 历史版本、各轮实验脚本、发布快照、隐藏备份目录、对比方法和已展开的第三方源码均在盘点范围内。相同代码位于不同版本目录时，保留各自路径，不因重复删除版本。

代码以本次盘点清单为边界，复制时逐文件记录 SHA256。原目录和正在运行的实验未改动。三人的目录归属表示整理、维护责任，周次表示计划上传批次，不表示原创归属或历史开发时间。作者信息、许可证、原始版本名保持原样。

Git 内部数据、node_modules、site-packages 等标准依赖安装目录、虚拟环境、缓存和已识别的安装版运行时不复制。历史工具目录和第三方源码快照保留。日志、模型输出、图片、压缩包和数据文件不作为源码批量搬运；若日志或运行现场目录中存在源码文件，则保留并标明用途。已有 ZIP/TAR 压缩包不重复展开，清单覆盖磁盘上已展开的文件。`未纳入文件.csv` 记录盘点中未收录的文件与原因。`outputs/` 下的报告生成及交付临时文件不属于本次算法工程源码范围。

## 文件怎么对应

例如：`lzh/第8周传/代码/projects/kz-dsh/src/policy.mjs` 对应原项目 `projects/kz-dsh/src/policy.mjs`。

文件清单提供原路径、整理后路径、负责人、周次、类别和内容哈希。共用模块只按原路径收录一次；跨版本相同路径前缀仍各自保留，基线与改进版没有混合。

## 如何运行

按分工和周次拆开后，相对导入可能跨周、跨成员。先用 Python 3.11 或更新版本将已交付内容还原到一个新目录：

```sh
python 交付工具.py verify
python 交付工具.py assemble --through-week 9 --output ../HaiAgent_组装源码
```

组装后按各子项目原来的 README 安装依赖和运行。第6至第8周只组装对应的累计内容，尚未交付的模块会缺失；完整工程以第9周组装结果为准。原项目中的服务器路径、模型配置、外部环境、评测数据和运行依赖仍需按实际环境配置。本次文件校验不等同于全部历史工程运行通过。

也可生成并回读核对按原路径还原的本地压缩包：

```sh
python 交付工具.py assemble --through-week 9 --output ../HaiAgent_完整源码.zip --zip
```

## 每周怎么上传

第6周只上传三个人的 `第6周传` 文件夹；第7周追加 `第7周传`，之后依次追加。不要一次上传整个四周目录。每次完成本周核对后再提交，提交说明写清本周内容。

```sh
python 交付工具.py export --week 6 --output ../HaiAgent_第6周上传.zip
```

导出命令只生成本地文件，不连接 GitHub。若本周存在疑似凭据，命令会停止，先依据 `公开上传前待核对.json` 检查和处理。该清单只记录路径、类型和行号，不展示凭据值。源码内的服务器配置、第三方许可和评测参考代码也应按实际发布范围核对。本次整理没有上传任何代码。
