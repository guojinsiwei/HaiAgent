分工
----
DSH：模型路由与请求、解题主循环、原生读写/终端工具、权限、会话及压缩。
KZ：如何保存和使用证据、何时换路线、如何分解和验收子目标；回溯默认冻结。
辅助角色也通过 DSH 的 LLM 接口；不另建 API 客户端或 Solver 循环。

四个核心模块
------------
1. 单题记忆 — src/memory.mjs、src/full-task.mjs、src/roles.mjs
   原始观察 E 与经验记忆 M 分开。Monitor 按真实输出的精确引文提出记忆；
   也接收 Solver 提交的证据关联记忆，以及确定性重复失败/明确测试记录。
   记忆包含条件、结论、操作、文件目标、证据和下一步；支持去重强化、
   依赖文件指纹、过期检查、关键词召回、条件重试、执行前适用性检查。
   模型总结仍标为可错的条件性判断，绝不把一次报错当成算法路线不可行。
   活跃记忆容量 24、每次召回最多 4 条；不是无限记忆。原始工具证据另存。

2. 探索 — src/policy.mjs、src/full-task.mjs
   已确认失败触发负面锚点和三维策略比较；提案绑定最终 bash 的准确参数。
   命令规范化、相关输入变化检查、记忆适用性检查共同影响放行。
   直接脚本观察显式路径、局部导入和配置；不把无关文件改动当修复。
   全项目构建/测试仍保守使用全工作区范围，不把几个清单当完整依赖图。
   文件改变后允许原检查；另允许一次有新观察支持的明确判别性重试。
   cat/head/tail/wc 的稳定文件结果可复用；跟随日志、进程查询、任意程序
   或合理复测不一刀切禁止。只改说明文字不算修复，未知外部状态保留不确定性。
   相似度只是启发式，不是数学正交证明。连续拒绝 7 次转建议模式，
   不杀死任务、不自动乱改文件，不绕过宿主权限或预算。
   没有新增 HAI 图搜索或两候选预测搜索；它们不属于这次迁移范围。

3. 结构化上下文 — src/structured-context.mjs
   持久保存事实、未解决问题、未完成计划、结论及证据编号。
   本轮没有再次提到某个问题，不会将其删除；关闭问题需要实际证据。
   默认结构化面板 24000 字符，其中记忆预留 8000 字符。超长内容变成
   明示的局部展示和可翻页引用，而不是致命协议错误；原文仍在本题状态中。
   这是 KZ 面板预算，不是 DSH 总上下文上限。最近六条证据只是面板窗口，
   不是把解题历史砍成六步。DSH 仍掌管会话压缩；最终物理位置由宿主决定。

4. 终端有效信息提取 — src/terminal.mjs、src/workspace.mjs
   清除 ANSI 颜色/光标控制序列，保留刷新前的错误帧；按测试、编译、
   安装等类别优先提取错误、关键诊断和尾部统计，保留行号及原文引用。
   不把 grep 没找到、截断、后台、超时、取消、被拒绝当成确认的策略失败。
   退出码 0 不等于任务完成；traceback、失败统计、未知管道阶段会阻止
   将其认定为干净检查。没有伪造管道各阶段退出码，拿不到就标未确认。

子目标与 1342
-------------
子目标：依赖 DAG、当前目标、验收定义、检查证据。只有真正执行对应检查，
且相关文件状态稳定，才能标记 check_passed；后续修改会使结果失效。
check_passed 仅表示该项公开检查通过，不是官方 benchmark 成功。

1 局部修正：格式/参数/语法错误先修具体问题，不立即强迫换算法方向。
3 只读侦查：简单只读动作豁免三维新颖性；原生读取保持可用，修改需记忆审阅。
4 完成审查：独立 Critic 先提公开检查、由 DSH 执行，再依据真实结果验收。
2 状态回溯：当前 backtracking:false，既不自动创建快照，也不自动恢复。
  原代码和显式开启的独立回归保留；模型不能通过工具修改此配置。
  不再把该机制的实验收益当作已证实。大型仓库快照扩展明确延期。

接入顺序
--------
DSH 组装请求 → KZ 更新子目标/检索记忆/注入证据 → Solver 选择动作
→ 必要时提交记忆适用性和策略调整 → KZ 路由与最终动作校验
→ DSH 执行 → 提取真实输出、更新记忆与目标 → 必要时 Monitor/Advisor
→ 宣称结束时 Critic 执行公开验收。

新增元数据工具：kz_update、kz_strategy、kz_history、kz_consult。
它们不是替代 shell；这些调用和辅助角色都计入预算，不能称为零成本。

自动 Monitor → Advisor 联动（0.2.1 补齐）
---------------------------------------
不再只等 Solver 主动调用 kz_consult。以下信号会排入待处理求助：
  - Monitor 基于至少两条实际证据判断 stalled；
  - 同一命令、同一可观察工作区、相同输出，实际执行失败连续 3 次；
  - 终端只读诊断连续 14 次没有工作区变化（仅是停滞嫌疑，不是失败证明）。
这些参数沿用旧 KZ；重复拦截不算执行失败，局部语法错误不算换路线依据。
native read/glob/grep/write/edit 等结果现在也归档为 E 证据，读文件类参与
只读停滞计数；它们不伪装成退出码为 0 的 shell 测试。原生异常也可见，但
不把基础设施/权限错误当作确认的算法失败。只返回的一页不能证明全文不存在。
待总结失败 ID 保留至有效监控审阅；超过近期窗口会从本题归档补入。
监控总额度仍为 12，分 6 次周期和 6 次异常，异常额度随任务进度释放。
8 次连续侦查给软提醒，不强制命令、不终止任务、不增加模型调用。

求助附带原始目标、触发原因、最近失败/触发证据、记忆及子目标。自动与手动
共用每题最多 6 次 Advisor、间隔 5 次宿主工具调用的冷却及总请求预算。
元数据调用也属于这个宿主工具计数；自动排队本身不伪装成一次 shell 调用。
冷却中的请求保留待处理；相关工作区变化、新的干净非侦查执行或 Monitor
给出 progress/necessary_retry 会撤回旧警报。同一证据模式不反复请求救援。
近期 32 个已求助模式保留用于去重，因此不是无限期全历史去重。
总请求只剩一次时留给 Solver，不为了向导另加预算。Advisor 失败、格式
错误、次数耗尽时记录原因并继续原解题流程，不自动执行建议、不停掉整题。

DSH 在 pre-step 之前已组装上下文，因此新记忆/建议通过宿主的持久消息接口
补入紧接着的 Solver 请求；不会只更新侧边状态而让模型晚一步看到。
审计事件：advisor_queued / advisor_pending_cancelled / advisor_trigger /
advisor_skipped / advisor_response / advisor_unavailable / pre_step_context_update。
没有据此宣称建议被模型采纳或已帮助脱困；这些仍需真实模型实验测量。

尚未验收的边界（不要直接声称可全量实验）
--------------------------------------
1. 已验收 Windows 离线算法和官方主循环；LLM/终端是脚本夹具。文件
   快照恢复测试使用真实临时文件。真实模型、Linux 原生 bash/回溯、
   长程压缩和进程崩溃恢复仍需目标环境验收；没有本轮 benchmark 成绩。
2. 模板保留 800 次 DSH stream / 600 次工具，并配置 7200 秒和每题 50 元。
   请求前按最大输入容量和明确的 maxTokens 预留，失败/缺失 usage 不退款；
   这些是历史实验费率上界，不是当前报价。无显式输出上限、路由/模型不符
   或带媒体时，计费保护拒绝派发，须先核准配置，不能擅自放大预算。
   所锁定 DSH 官方文本 API 适配器源码无普通内部重试；附件 stale-id 重试路径
   不在本配置范围。外层 stream 重试均计数。付费线路实际请求数及账单仍待
   小测验收，不能把逻辑 stream 数普遍宣称为任何提供商的真实 HTTP 次数。
   未更改 DSH 原生上下文、模型温度、thinking、工具超时；repair6 仅为工具
   参数 JSON 损坏增加受原生重试额度约束的请求恢复兼容层。
   7200 秒在派发新请求/工具前检查；已运行调用仍由宿主取消和超时负责，
   不是新增一个强杀在途命令的看门狗。
3. 工作区指纹默认观察上限 20000 文件、64 MiB，遇到超界/符号链接/读失败
   返回 unknown，不是停止执行。当前回溯冻结，不为此扫描/保存自动检查点。
   文件状态不能证明外部依赖、服务、环境完全不变。大文件的依赖哈希性能
   仍需真实仓库验收，不能宣称已支持任意规模。
4. 共同配置暂禁 DSH 原生委派 Solver（subagent/fork/workflow），避免未经
   验收的跨子代理预算和并发文件回溯；内部 Monitor/Advisor/Critic 保留。
   两组都应用同一个 common 配置，不能把该基线称为完全默认的官方 DSH。
5. 辅助角色有调用冷却和上限；不可用会留明确记录，不伪造验收或让全题
   因一个辅助 JSON 失败而终止。源码中这些设置仍需真实实验调优。
6. 各题必须独立 session、工作区、审计目录；插件应与实际执行目录同机。
   不支持用本地哈希判断远端工作区。同一 session 不允许两个进程同时写。
   审计保留任务原文和工具输出，可能含私有数据；不要把密钥放进命令或任务。
7. 候选宿主版本锁定 rc.2；未运行 npm 原生安装脚本。目标 Linux 依赖仍需
   单独验收。应使用新鲜实例，不直接覆盖历史实验容器或混算新旧分数。

本轮：未调用付费 API、未部署服务器、未启动 benchmark。
