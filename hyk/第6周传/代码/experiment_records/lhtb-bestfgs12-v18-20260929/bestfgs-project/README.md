# BestFGS 0.18.0：连续执行、按需探索

独立开发版本，基于 reliability-v17。云端 HAI 12 题及旧冻结实验未修改。
这是算法结构变化，不再默认运行旧全局语义 Best-first 前沿调度器；论文应标为新变体。

## 主流程的减法

- 去掉每条命令后的 assessment 和 memory 模型调用。
- 去掉初始语义地图、强制多宏动作、覆盖度与阶段压力调度。
- 去掉提交必须附带复验命令、评估通过及额外检查轮次的要求。
- 去掉每条命令复制工作区/提交 Docker 镜像的执行模式。

主模型持续工作，可执行 run、consult、checkpoint、restore、submit 五种动作。
默认入口 `best-fgs`、`cli-retrac-best-fgs`、`python -m bestfgs` 和包级
`bestfgs.TaskRunner` 使用新流程。旧代码可通过 `LegacyTaskRunner`、
`bestfgs.agent.TaskRunner`、`best-fgs-legacy` 显式使用。
继承的根目录 run_*.py 历史实验脚本尚未移植，不能当作 v18 启动器。

## 顾问、分支和记忆

顾问触发：主模型针对具体困难主动求助；同一命令连续三次在相同可观察工作区
产生相同失败输出；或长时间只读诊断而没有进入区分性检查/实现。只读诊断先得到
轻量收敛提醒，达到更高阈值才调用顾问。没有文件变化本身不会被判成失败。
顾问最多提出两条假设、区分性检查、与已有尝试的区别和证据引用，没有执行权。
默认最多 6 次，两次间至少 5 次工具调用；与主模型共享模型请求和墙钟预算。
这些是待实验检验的初始参数。可选顾问输出失败时主模型继续，明确鉴权/余额错误停止。

图仅保存显式候选。默认最多 3 个活动候选、12 次检查点创建（含初始状态）。
恢复前保存当前方案；容量不足时拒绝切换并保留当前工作。退休快照保留供审计。
文件快照不声称保存进程、网络或外部服务。Docker 桥接保持一个活动容器，
保存候选/交付才 capture。恢复不会恢复预算或抹去其他路线的任务内记忆。

可选记忆随主模型动作提交：kind、conclusion、condition、operation、targets、
next_step、evidence_ids。记忆既可描述阻塞，也可保存已证据支持的可复用途径。
只接纳当前请求可见的真实证据编号，结论仍是证据关联的模型陈述，非已证因果规律。
最多保留 24 条；固定上下文区域展示最多 4 条，按词项匹配、作用域、近期性排序。
带 targets 的记忆只比较相关文件/目录指纹：无关文件变化不会误使其失效，目标变化则
明确标为待复查。没有 targets 时退回保守的整个工作区适用性。外部环境始终未验证。
当主模型提出的具体命令与当前仍适用的目标、操作或语义高度匹配时，执行前只提醒一次；
模型可以换方向、检查条件，或用 uses_memory 明示后有意识地继续。它不是硬禁令，
也不会因为同一工作区内换一种命令写法而反复打断。
任务指令和最新反馈保留完整，旧交互按预算裁剪；常见 Bash 工具沿用确定性输出压缩。

固定上下文还包含 delivery_progress 与 budget_pressure。前者从公开题面中保守提取明确
交付路径，显示缺失文件，但永远不把“文件存在”当成正确；后者在 60% 预算后要求收敛，
85% 后要求保存最佳状态并补齐交付差距。二者只 push 求解，不接管模型的提交判断。

## 日志与指标

- `audit/events.jsonl`：带哈希链、同步落盘、凭据清洗的全部请求/响应/工具反馈。
- `audit/graph.json`：候选、父节点和恢复边。
- `audit/memories.json`：当前记忆与证据来源。
- `audit/result.json`：工具调用、总请求及主模型/顾问分项、token 用量、各角色耗时、停止原因。

interaction_rounds 明确包含主模型及顾问请求（含失败请求），action_rounds 单列。
与旧版轮次比较需从日志对齐口径，不直接混算。official_success 始终为 null，
由外部官方评测记录；提交/退出零不当作成功。
工具冗余保留真实分母及待独立语义审计状态，未标注时 rate=null，不用机械重复率代替。
机制利用记录记忆接纳/拒绝/曝光/模型自报引用、动作前提醒、提醒后是否改动作、下一次
工具是否成功/改变工作区、顾问调用/接受/降级、建议后的首个动作、保存/恢复次数。
日志把“提醒→重考虑→实际工具结果”串成行为链，但曝光、自报引用、行为改变或随后成功
均不能单独证明因果收益；最终仍需配对实验和消融。

## 使用

Linux/WSL、Python 3.11+，离线检查不调用付费模型：

```bash
python3 -B verify_lean.py
```

在隔离 Linux 沙箱中执行，Key 从环境变量读取：

```bash
PYTHONPATH=src python3 -B -m bestfgs \
  --workspace /path/to/task --run-root /path/to/new-run \
  --goal '任务说明' --provider deepseek --model YOUR_EXPLICIT_MODEL_ID
```

本地执行器本身不是操作系统安全沙箱，须置于隔离环境；仅支持 Linux/WSL 进程组清理。
`bestfgs.lean_lhtb.run_lhtb` 为未来冻结实验提供桥接：传入既有 host-only DockerState、
任务、两个独立客户端、日志目录及官方二元续跑回调。父调度器仍负责外层超时、
资源限制、官方评测、清理与故障分类。旧适配器不能直接换包后假定已接入新算法。
本次只做离线回归和适配契约验证，真实 Docker/Harbor 交付需部署前单独验收。
