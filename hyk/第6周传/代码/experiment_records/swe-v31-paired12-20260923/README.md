# DeepSeek-V3.1 任务内记忆补充对照

- 目的：探索模型能力降低后，BestFGS v12 相对 Raw 的配对差值是否改变。
- 数据：从已经准备完成的 100 题 SWE 开发队列按固定哈希种子取 12 题；不按历史结果筛选。
- 方法：同一 12 题分别运行 BestFGS v12 和 Raw，共 24 次方法运行。
- 调度：两个 CubeStudio 容器各承担 6 题；一道题的两种方法在同一容器运行，方法先后次序按任务 ID 哈希交替。
- 模型：阿里云百炼 `deepseek-v3.1`，思考开启；temperature=0.6，top_p=0.95。
- 预算：每次最多 24 个决策、80 次 CLI 调用、每决策 6 条命令，任务超时 14400 秒。
- 成功率必须以后续 SWE-bench 官方 harness 为准；内部成功不能当最终结论。
- 这是 12 题探索性实验，不用于宣称总体成功率提升。
- API Key 仅在启动时通过 SSH 标准输入交给远端进程环境，不写入项目、协议或结果文件。
- 每个 worker 启动前各发送一次最多 4 token 的认证/模型可用性请求；这是付费但可忽略的小请求，不计入 24 次正式方法运行。

正式启动前需要用户在百炼控制台取得可调用 `deepseek-v3.1` 的 API Key 和业务空间 Base URL。
