# 2026-09-14 实验问题修正

适用项目：桌面完整版 BestFGS。正常 SWE / Terminal 启动命令继续兼容。

## 独立成功审计

- Judge 查看从当前任务初始快照到最终候选的累计补丁、变化路径和实际文件清单，避免只看最后一步。
- 格式校验失败在同一候选和证据上最多修正一次。枚举大小写可归一化；未知风险 ID、虚构证据和缺失风险检查仍不放行。
- `--success-judge-max-calls 2` 现在表示最多两个格式有效的审计结果；修正请求额外计费，最多四次客户端调用。底层网络重试次数仍由已有模型配置控制。`judge_calls` 记录真实客户端调用数，`valid_judge_calls` 记录有效审计数。
- required 模式遇到审计不可用或额度耗尽时，保留候选并以 `judge_unavailable` / `judge_budget_exhausted` 未验证收尾，交给官方评测；不伪装为成功，也不把基础设施错误新增为语义探索方向。
- 有效的 fail / insufficient_evidence 会要求补充具体检查；原候选可以只补验证，无需为了再次参评而进行无意义修改。

## 验证与任务要求

- 普通候选功能验证及最终复验均在一次性副本执行，测试生成的二进制和报告不进入最终提交。
- 验证改写既有候选文件会导致验证失败；常见测试缓存和 Git 元数据不作为实现修改。
- 求解与审计提示同时要求核对全部明确条款、输出位置与文件限制、正例、负例/边界、关联类型和操作、状态副作用及题面要求的性能条件。它仍是基于公开证据的检查，不保证隐藏测试通过。

## 图搜索恢复

- 节点规划次数不再假设每批一定能生成三个动作；模型每次返回一个动作时，仍可填充实际 3..6 容量。
- 空前沿且有剩余预算时，整题最多两次定向恢复。无文件变化的工具缺失、路径错误、超时分支可退出活跃容量，但原边、失败证据及重复动作记录保留。
- 不放松执行器的禁止操作；被安全约束阻断的动作不获得环境恢复容量。
- 引导模型正确处理预期失败的探测命令；单命令显式超时上限由120秒调整到300秒，默认执行超时和题级轮次/工具预算保持原设置。

## 指标

- 官方评测完成后按任务 ID 关联官方成功/失败，计算两组平均交互轮次。
- 缺少官方结果的任务单独记录，不自动当作失败；缺少轮次记录不补零。
- 原内部统计保留于 `agent_diagnostic`，误报/漏报记录在 `agent_vs_official`。
- `refresh_experiment_reports.py` 可离线校正旧实验的统计，生成独立 JSON，不重跑 Agent、Docker 或官方测试，也不覆盖原始实验报告。

本次没有更改冻结题单、模型选择、基础24轮/80工具及复杂度调度，也没有引入跨任务记忆。后续效果需要在同题、同模型条件下重新测量。
