# SWE 100 题自动化实验

本轮采用：**Cube-Studio 自动配环境和搜索 → 下载一个结果包 → 本机官方 Docker harness 批量评测**。
SSH 尚未配置，因此下载仍需手动一次；不用申请 SWE 云评测 API，也不是向排行榜投稿。
没有自动启动任何 100 题付费模型实验。

## 固定的实验定义

- 清单：`examples/swe100-plan.json`，SWE-bench Verified 随机 100 题，种子 `20260918`。
- 排除本项目冻结测试集、导出时可识别的历史题目，以及已跑的 `sympy__sympy-16450`。续跑不重新抽样，不因环境失败换题。
- 来源的 Hugging Face split 名为 `test`，但本项目将这批题用作**非冻结开发实验**；并未动用你保留的冻结测试集。
- 共 9 个仓库：Django 50、SymPy 13、scikit-learn 10、Sphinx 8、Matplotlib 5、xarray 4、Astropy 4、pytest 3、pylint 3。
- 清单只有公开问题、基准提交和环境配方，不包含参考补丁、评测测试补丁、FAIL_TO_PASS/PASS_TO_PASS 标签。
- DeepSeek / `deepseek-flash`，`success-judge-mode=off`。每题默认固定 24 轮、80 次工具调用、4 小时进程上限；关闭自适应预算扩张。不是 80 次 API 调用或金额上限。
- 若要改预算，**首次 prepare 时**指定 `--max-iterations`、`--max-tool-calls`、`--task-timeout`，后续 run 使用同样参数；代码、清单和预算写入批次身份，续跑不允许悄悄改变。
- 搜索逻辑不改；新增快照源码导入保护，避免任务运行时误用环境里 editable install 指向的初始源码。

## 1. 上传并准备环境（现在先做这一步）

将 `BestFGS-swe100-20260918.zip` 上传到 Jupyter 文件区根目录（终端对应 `/mnt/lizh639`）。
在 Jupyter Terminal 执行：

```bash
cd /mnt/lizh639
/mnt/lizh639/envs/bestfgs/bin/python -m zipfile -e BestFGS-swe100-20260918.zip .
cd /mnt/lizh639/BestFGS-swe100
bash start_swe100.sh prepare --install-system-deps
```

压缩包包含新的 `BestFGS-swe100` 文件夹，不覆盖原来的 `/mnt/lizh639/BestFGS`。
首次解压后不要在运行过程中重新覆盖此文件夹。

这条命令会进入名为 `bestfgs-swe100` 的 tmux 会话，自动：

1. 安装明确列出的系统构建依赖（需要 root；不执行 apt upgrade）。
2. 按官方缓存的版本固定环境 YAML 创建依赖基础环境，再为每题克隆独立环境。
3. 拉取题目基准提交、安装该版本项目、检查复制后的快照能否导入自身源码。
4. 保存准备状态、环境版本和日志；失败保留记录，继续准备其他题。

`prepare` **不调用 DeepSeek、不读取参考答案、不跑官方隐藏评测**。
100 题的原生依赖可能下载/编译较久。平台网络、软件源、系统库、磁盘配额仍可能造成 `prepare_error`；脚本不会假装全部准备成功。
若 Conda 要求接受软件源条款，需你阅读后自行决定，脚本不会代为接受。Notebook 环境不是官方 Docker 镜像的完全复制，最终成绩仍由独立官方 Docker 环境判定。

## 2. 查看进度、断开电脑与恢复

另开一个 Jupyter Terminal：

```bash
cd /mnt/lizh639/BestFGS-swe100
bash start_swe100.sh status
```

输出各状态数量，以及当前题目和错误。详细日志在：

```text
/mnt/lizh639/bestfgs-runs/swe100-v1/system-setup.log
/mnt/lizh639/bestfgs-runs/swe100-v1/prepared/<题目ID>/prepare.log
/mnt/lizh639/bestfgs-runs/swe100-v1/runner.log
/mnt/lizh639/bestfgs-runs/swe100-v1/search/<题目ID>/<题目ID>/attempt-*/agent.log
```

安全离开 tmux：先按 `Ctrl+B`，松开，再按 `D`；快捷键被浏览器截获时，在另一个终端执行：

```bash
/mnt/lizh639/envs/bestfgs/bin/tmux detach-client -s bestfgs-swe100
```

重新进入：

```bash
/mnt/lizh639/envs/bestfgs/bin/tmux attach -t bestfgs-swe100
```

tmux 内的云端任务不依赖你电脑保持开机，但**Notebook 容器不能被平台停机或回收**。本机 Docker 评测时电脑则需保持开机。
脚本结束会留在 tmux 的 shell 中；已有会话时先 attach 查看，不重复新建。

## 3. 正式搜索（准备检查后才执行，会付费）

建议先确认 100 题都是 `prepared`，修复环境问题后再开始。进入上述 tmux 会话，执行：

```bash
cd /mnt/lizh639/BestFGS-swe100
bash start_swe100.sh run
```

未设置密钥时会隐藏输入 DeepSeek Key，不要把密钥发到聊天里。
每次 run 会先发一个很小的真实 API 请求检查连通性，通过后串行执行任务。
每题结束自动保存补丁、状态与结果包；模型不可用时立即暂停整批，连续 3 个搜索基础设施错误也会暂停。
API 检查不保证后续网络一直正常；API 用量记录不是扣费账单。

中断后重新执行同一命令：完成的题（包括正常搜索但没解出的题）跳过；中断题从新的一次尝试开始，**不是恢复进程内的搜索图**。
错误题默认不自动重跑；修好原因后显式重试：

```bash
bash start_swe100.sh prepare --retry-errors
bash start_swe100.sh run --retry-errors
```

仅需重试搜索错误时，直接使用第二条。不要为了提高成绩反复重跑正常完成但未解出的题。
旧尝试保留，已有用量记录计入汇总；被强制中断的请求用量可能不完整。
数据保存在持久目录，剩余空间低于 20 GiB 时暂停。`df` 显示的共享盘剩余量不等于个人配额；平台配额须另行确认。

## 4. 下载一个结果包并本机评测

结果包会在每题完成后自动更新：

```text
/mnt/lizh639/bestfgs-runs/swe100-v1/evaluation-bundle.zip
```

Jupyter 文件面板路径是相对根目录的，进入 `bestfgs-runs/swe100-v1`，右键下载 `evaluation-bundle.zip`；不要把 `/mnt/...` 直接当作文件面板路径。
结果包只含补丁、状态和环境说明，不含 Conda 环境、工作区快照、密钥或模型提示日志。
默认评测要求所有题都已结束；基础设施失败题仍保留在 100 题分母中，不会被自动剔除。中途查看必须显式使用 Python 入口的 `--allow-partial`。

本机 PowerShell 执行（下载位置使用默认 Downloads）：

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\BestFGS\evaluate_swe100.ps1"
```

入口自动检查/启动 Docker Desktop，使用本机已安装的 Ubuntu WSL 官方 SWE-bench harness：
`/home/research/SWE-bench/.venv/bin/python`。
不调用 DeepSeek，也不依赖之前失败的 `sb-cli gen-api-key`。
首次遇到新仓库可能下载大镜像，100 题不是瞬间完成；默认串行减少内存压力。

输出目录：

```text
桌面/BestFGS/benchmark_results/notebook-official/bestfgs-batch-<补丁文件摘要>/
  results.json           # 官方通过率、状态与已记录用量
  results.csv            # 每题结果
  harness.log            # 官方评测进度
  logs/run_evaluation/   # 逐题官方 report.json 和测试日志
```

重复同一命令会复用已有官方结果；存在活动评测容器时拒绝重复启动。
中断后若仍有活动容器，先等其结束或检查对应容器，勿批量清理其他实验容器。
区分 `resolved`、`unresolved`、`empty_patch`、`evaluation_error`，不要把 agent 自检成功当成官方通过。
`results.json` 的分母始终为固定选题数；环境失败率应和算法未解率分开报告。

SSH 配好后可用下面命令自动拉取结果包，省去手动下载（目前未验证你的 SSH）：

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\BestFGS\evaluate_swe100.ps1" -RemoteHost cubestudio_container
```
