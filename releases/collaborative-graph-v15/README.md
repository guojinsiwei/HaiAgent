BestFGS 是一个独立的**阶段自适应语义最佳优先图搜索**（Phase-Adaptive Semantic Best-First Graph Search）项目。

## 核心机制

1. 模型先生成语义地图和一个 Bootstrap 动作。语义方向只是任务空间的先验划分，不表示已经探索。
2. 搜索维护全局 `(状态, 动作)` 前沿，每轮在所有可达状态中取优先级最高的一项。
3. 超预算、已执行、已覆盖和命中精确 avoid 的失败动作先被硬过滤；遵循语义 avoid、明确采用替代方法的动作获得在线规避优先级，再进入全局前沿。
4. 求解压力 `p∈[0,1]` 平滑融合完整预算进度（0.55）、核心语义覆盖（0.25）和真实候选成熟度（0.20），保持单调但不再在约四分之一预算处直接饱和。达到求解阈值或形成成熟候选后进入求解模式。
5. 同一套优先级连续变权，不做 Beam→Best-First 的硬切换，也不在切换时删除旧分支。

优先级主分量如下：

| 分量 | 前期权重 | 后期权重 | 依据 |
| --- | ---: | ---: | --- |
| 真实进展 | 0.20 | 0.35 | 命令、修改、验证等真实反馈 |
| recommend | 0.10 | 0.25 | 当前任务、当前状态下仍有效的成功经验 |
| 语义新颖性 | 0.30 | 0.05 | 未探索方向优先 |
| 信息增益 | 0.30 | 0.10 | 是否指向未解决问题并声明可观察证据 |
| 候选成熟度 | 0.10 | 0.25 | 修改、验证及候选动作信息 |

最终分数还扣除工具成本、重复方向和失败历史，并加入最高 0.10 的等待老化奖励，防止低分方向永久饥饿。`recommend` 在前期参与加权；进入求解阶段后，只要全图仍有可执行 Recommend，前沿就先利用它，耗尽后才恢复普通搜索。方向失败会使其推荐置信度按 `1/(1+失败次数)` 衰减。Avoid 分成两种真实作用：相同失败命令/动作直接过滤，显式避开失败策略的替代动作获得规避加分。当前实验不再生成独立 Judge 验证缺口或使用其反馈控制搜索。

优先等级先于同等级分数：

- 4：历史 Judge 缺口精修带，当前实验不启用；
- 3：有强真实进展或高成熟度候选；
- 2：有中等真实进展，或中后期的有效 recommend；
- 1：能带来新语义或信息；
- 0：兜底动作。

## 动作容量与图结构

每个状态的语义动作容量动态保持在 **3–6**：基础容量为 3。只有尚未形成成熟候选、存在多个独立未覆盖语义方向，且前沿分数接近或方向反复失败时，容量才逐步增加到 6；成熟候选出现后回到 3。容量不读取访问次数，因此不是 progressive widening，也不会僵硬地固定为 2。

前期每个语义方向在待选前沿最多保留 1 个动作，求解阶段最多保留 2 个替代动作。这只控制候选多样性，不像 Beam Search 那样要求同层动作全部执行。语义等价且工作区指纹相同的状态可保守合并；旧分支始终保留，可在主路线失败后重新被全局队列选中。

## 成功、预算与记忆边界

- 默认基础预算为 24 轮 / 80 次工具调用；题面判定为难题时为 33 / 108。默认 `budget_multiplier=1`，不会自动扩成数倍预算。
- 工具预算的 10%、最多 8 次保留给最终复验。
- 模型的 `task_success` 只作诊断；真实候选修改、执行检查和功能测试通过后形成 `candidate_success`。恢复旧逻辑：结合求解模型整理的成功标准达标项生成内部 `verified_success`，随后停止并在交付前复验；不调用独立审计模型。内部标签不等于官方评测结论。
- 长程记忆严格限于**同一道任务**的跨轮次和跨分支。每次 `TaskRunner.run()` 都新建规则库、知识板和搜索图，不把上一题经验送入下一题。
- 初始语义地图冻结为“核心方向”，核心覆盖率用于阶段切换和在线奖励；运行中新发现方向只影响动态发现覆盖率，因此不会因为分母临时扩张而产生虚假负奖励。文件修改导致旧证据失效时，核心覆盖仍允许真实下降。
- 有效探索比例、知识复用率和工具冗余率继续作为事后指标，不参与在线分数；知识复用率同时统计Recommend复用和Avoid规避。另输出完整经验漏斗：两类规则的生成、召回暴露、适用性校验、进入前沿、执行、生效，Recommend触发利用优先，以及Avoid精确阻止和全阻止兜底。

官方评测结束后，成功/失败任务平均交互轮次按官方标签计算，内部口径保存在 `agent_diagnostic`。旧实验可用 `refresh_experiment_reports.py` 离线生成校正摘要；详见 [本次改动说明](CHANGES_20260914.md)。

撤下的是额外的结果审计 LLM，不是负责动作生成、转移理解和上下文压缩的求解模型。旧版内部判定仍包含求解模型整理的达标项，因此不能把它描述成完全机械的任务正确性证明。最终研究指标仍以独立官方评测为准。历史 Judge 类与显式库级测试保留用于读取/复现旧实验，但不接入当前运行入口；输出兼容字段为 off / 0 / 空列表。

BestFGS 的 `best_first_runtime.py` 独立拥有搜索生命周期、预算、快照转移、RE-TRAC、候选管理和最终复验。`SemanticBestFirstGraphSearch` 在它之上实现阶段自适应全局前沿。Python 包名为 `bestfgs`，CLI 与 benchmark 直接使用这套运行时。

运行时依赖方向如下：

```text
TaskRunner / CLI
    -> BestFirstSearchRuntime
        -> SemanticBestFirstGraphSearch（全局前沿与阶段优先级）
        -> environment / semantic / rules（组合服务）
```
