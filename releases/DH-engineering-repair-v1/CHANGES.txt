DH engineering repair v1 — 2026-10-04

Base: releases/DH (frozen original left unchanged).
Status: independent candidate; Linux offline validation completed in an isolated
temporary directory. Not switched into any production experiment. No benchmark
rerun, model API calls, algorithm-threshold change or budget increase.

Repairs
1. Resolve a literal leading `cd DIR &&` when extracting command dependencies.
   `/app/cow/kernel/vm.c` is no longer confused with `/app/kernel/vm.c`.
   Ambiguous shell branches/expansions stay unknown instead of guessed.
2. Align literal inner QEMU timeout with outer command timeout and a 10-second
   collection allowance, bounded by the existing command cap and task deadline.
3. On sandbox timeout, recover bounded tails of literal redirected logs confined
   to that task image. Skip unchanged old logs and symlink escapes. Preserve the
   nonzero exit/timeout; recovered text is NOT a test-pass signal.
4. Audit known xv6 init.c test-only boot substitutions before delivery. Feed the
   issue back for correction; do not silently revert edits. Apply the same public
   delivery guard to DH and RAW. Budget exit with a broken boot guard is recorded
   separately, preserving the original stop reason in the audit event.
5. Make active contrastive proposal fields explicit in the context. Distinguish
   schema rejection from similarity rejection and return concise repair fields.
   Do not invent orthogonality proofs or bypass existing exploration checks.

Limits
- Real QEMU guest input/lifecycle and official LongCLI scoring have not been rerun.
- The timeout parser handles literal shell QEMU invocations, not arbitrary shell
  programs or a general terminal/PTY driver.
- Redirect-log recovery is integrated in harness/environment.py's shared sandbox;
  other executor backends do not automatically gain image-root log recovery.
- The boot guard targets recognizable literal init.c boot substitutions; it is not
  a complete C parser or a general temporary-edit rollback mechanism.
- The original rigid gate policy, regeneration budget and repeated-call policy
  are unchanged. This patch does not promise that persistent model loops disappear.
- Shared DH/RAW executor changes must be applied together in any future comparison;
  old experiment scores remain immutable and do not measure this patch's effect.
