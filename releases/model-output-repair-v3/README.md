# BestFGS 输出与错误分类修复 v3

本版本在 `mechanism-conversation-fix-v2` 上修复六题试跑暴露的模型输出恢复与报告问题。
本地专项回归、云端完整回归已通过；真实 Docker 验收结果见 `VALIDATION.md`。

## 改动

1. 截断反馈：`finish_reason=length` 后，在原有有限重试内明确告知输出被截断、
   当前输出 token 上限，以及把长代码拆成小段动作的要求。回复未完整通过验证前不执行命令。
2. 跨轮恢复：一次逻辑调用重试失败后，下一轮保留 `output_length` / `json_syntax` 等具体原因
   和纠错提示；原来只有笼统的“模型调用失败”。主动作上下文同时显示实际输出上限。
3. 预算保持：4096-token 输出上限、最多两次 wire 尝试、三次连续错误退出、任务总预算均保留。
   纠错文字占用已预留的 1024 字符，更新最后一条 user 消息，不改写早期会话。
4. 审计：外层日志保留安全枚举形式的错误原因，不再把 JSON/长度错误全变成 `null`。
   正式适配器显式启用脱敏后的失败回复诊断文件，保存有界首尾片段与摘要哈希。
5. 分类：同一角色后续收到成功回复且正常以预算/提交结束时，之前的错误标为恢复告警，
   保留错误次数。其他角色的回复不能代替恢复；终止错误、凭据错误、交付异常仍明确记录。

“要求分段”是提供给模型的恢复协议，不保证模型每次遵从，也不自动执行不完整代码。
本次未证明真实模型截断率已经下降，未重新运行付费正式题目。

## 开发优先级

建议优先投入 BestFGS，HAI 暂时作为已修复的固定对照。HAI 源码 21 个 Python 文件
与 v2 完全一致，本次只改变共用审计对错误原因的记录，没有重设 HAI 的决策规则。
HAI 后续仍应修复明确的工程缺陷；暂不并行改写两套算法。

理由是 BestFGS 已能产出有价值的方案，同时还有清楚的可检验问题：六题没有成功接纳记忆、
没有恢复分支，四题用满 600 次工具调用；需要优先分析重复读/试与实际进展，
再单独检验建议介入是否增加有效编辑、记忆是否有增量收益。

不要把本轮均分比值当作稳定优越性。相同六题的历史描述性比较为：

| 版本批次 | BestFGS 均分 | HAI 均分 |
|---|---:|---:|
| 上一轮 12 题中的同六题 | 0.2227 | 0.2264 |
| 当前 v2 六题试跑 | 0.2499 | 0.1019 |

两轮独立运行，均为小样本；模型轨迹、工程改动与策略行为共同影响结果，不能据此归因。
当前差距较大的一部分来自 HAI 本轮下降，HAI 的停滞机制值得保留为后续独立研究问题。
