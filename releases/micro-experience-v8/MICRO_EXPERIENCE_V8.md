# v8：条件化微经验怎样与探索相接

本地开发版，2026-09-21。基于独立保留的 v7；不修改云端、裸模型实现、统一三指标、题单和既有实验。没有启动 DeepSeek 调用、100 题重跑或官方评测。

## 1. 数据分两层，观察不等于因果经验

底层 `ExperienceRecord` 保留每次真实命令/自动检查/功能检查的返回码、输出摘要及哈希、节点、迭代、执行条件、文件依赖和 channel/index。上层 `MicroExperienceIndex` 合并同动作签名、同已观察条件、同结果的记录，所有原始来源 ID 都留下。已知依赖不同或输出不同不能合并；依赖不明时保守隔离记录的快照。重复次数不提高置信度或搜索分数。

在原有的转移评估模型响应中，可选返回最多 3 条 `micro_experiences`，不另开一次模型请求。例如：

```json
{
  "operation": "normalize_input",
  "target_paths": ["src/normalize.py"],
  "premises": [{"subject": "input", "predicate": "equals", "value": "None"}],
  "source_channel": "functional_validation",
  "source_index": 0,
  "lesson": "The observed None input failed when handled as a string; this explanation needs checking.",
  "next_check": "Check None and non-empty strings after repairing the input guard."
}
```

这是一条**有实际来源的模型条件假设**，不是已证明“所有 None 都导致此失败”的规则。程序绑定本轮指定 channel 的第 index 个真实结果；不存在的来源拒绝。坏的可选字段逐条丢弃并计数，不令一次有效模型转移整体失败重试。超时、拦截、截断等来源不能被提升成完整证据。

本版合并是确定性的条件/动作/结果键合并，不是无损自然语言语义聚类。同义但写法不同的解释仍可能分开保留；不会为了减少条目数量而把相反结论压成一个“规律”。

## 2. 规划前：索引召回与有限活动视图

建立操作键、文件路径、特异词、方向和命令签名的倒排索引。优先考虑当前未解决问题和未完成计划，再结合任务上下文、显式文件与语义方向。按类别/操作/目标分组选择多样性条目，避免同一类重复观察独占 Top-k；默认条数仍是 5。

当前检索分数为 `12×当前问题文件命中 + 3×min(当前问题特异词命中数,4) + 4×上下文文件命中 + 2×方向命中 + min(上下文特异词命中数,4) + 原证据条件有效`。布尔命中按 0/1。词项采用英文词项和中文二元片段，排除通用词；这是固定启发式，权重未经过效果优化。它只决定哪些经验进入活动视图，**不改变 BestFGS 搜索奖励或按引用数加分**。

原始来源完整保留，提示视图最多携带最近 3 个来源 ID 和总来源数。提示有总字符预算；完整前提和来源优先，放不下的整条不投影。没有召回不代表不存在历史反例。局部相关性排序是可审计的启发式，不是训练的相似度模型或经验效用估计。

## 3. 候选后：操作和对象匹配，再逐项检查前提

动作可声明 `experience_operation`、`experience_targets`、`experience_premises`。这些字段不参与动作身份或奖励；同一命令改写经验描述不能逃避重复检查。

候选匹配先找索引候选，再要求具体操作相同且目标文件或前提主体相交；双方明确声明目标文件却完全不相交时，不能仅凭同名 `input` 前提匹配。只有 `python` 等通用词相同不够。原始观察另有精确命令与工作目录匹配通道。操作键的规范化只是有限字符串处理，不理解任意同义改写；模型应复用提示中的稳定键。

动作级审计默认最多 3 条，排序按 `8×精确命令 + 4×操作 + 3×文件 + 2×主体` 命中加权，再做类别多样性选择；若确有通过上述作用范围门槛的条件假设，至少给它一个位置，避免全部被原始读取记录挤掉。原始只读重复判断有独立的全签名通道，不受这个 Top-k 限制。

逐项前提检查分两类：

| 前提 | 实现 | 能说明什么 |
| --- | --- | --- |
| `file_exists` / `file_absent` | 检查当前工作区内的字面路径 | 当前文件存在或路径缺失 |
| `file_contains` / `file_lacks` | 有大小上限的 UTF-8 文件字面子串检查 | 该字符串是否出现，不是 AST/程序语义分析 |
| `equals` / `not_equals` | 与候选动作对同一主体的声明作精确值比较 | 只说明声明一致/改变，不证明环境或输入真如此 |

路径越界、链接/重解析点、无法读取、超大文件或非 UTF-8 等情况返回 unknown。不执行模型提供的判断代码，不联网读取前提。内容检查当前上限为每文件 2 MiB。文件读取有边界，但不是整个系统状态的原子事务快照。

这些文件检查属于新增的本地运行时计算和 I/O，不是 CLI 命令，因此不进入原工具调用计数；不能据此宣称开销为零或公平地节省了同等工具成本。索引的 `premise_checks`、`file_read_operations`、`file_read_bytes`、`premise_check_seconds` 单独累计前提检查成本，不含原有来源依赖哈希检查的开销，不能当整个经验模块的总成本。缓存仅限一次同步检索/匹配调用，下一次动作或分支检查重新读取，不跨状态沿用。

多个条件按合取处理：不能只命中其中一条就声称整体适用。一个明确改变的条件会标记 changed；语义声明改变是 declared_changed；声明一致是 declared_match；证据不充分是 unknown。审计同时保留**原始证据依赖有效性**与**逐项前提检查结果**，不能把“声明一致”误读成“旧原因已经验证”。

## 4. 匹配怎样影响真实探索

- 规划前把条件、来源、失败观察和下一次检查建议提供给既有规划调用。模型可修改前提、选择替代动作或提出区分性检查。这是一般语义微经验的主要利用位置。
- 候选后记录匹配理由、每个前提状态、来源和建议。软匹配本身**不重写命令、不立即触发另一次模型评审，也不阻止当前动作**。动作执行后，其匹配反馈携带到子节点的下一次正常规划，明确标为旧状态，要求重新检查。它不进入已验证事实库。反馈扣除外层说明后的单条预算不超过 480 字符，JSON 内空白转义以保持字面条件；放不下的合取条件整体省略并提示重新查索引，绝不把截断前提当作完整条件。
- 程序性干预保留 v7 的窄范围：条件未变、证据完整的白名单只读重复批次可复用旧观察；适用的公开失败检查最多一条在现有工具预算内重跑。任何模型条件解释都没有新增硬拦权限。
- `next_check` 是文本建议，不自动当命令执行。已改变前提允许重试，但不宣称新方案成功。

因此本版不是“匹配后立即让模型修订当前候选”的双调用系统，也不是自动选择最优区分实验的假设搜索器。语义提醒能否被真实模型正确采纳，仍要通过小规模模型实验测量。

## 5. 留下什么证据，如何验证

结果/检查点的 `experience_report.micro_experiences` 含聚合条目和完整来源列表；`micro_index` 含条目数、索引与聚合诊断；`decisions[].micro_matches` 含动作级匹配解释；`runtime_events.micro_feedback_carried_to_child` 记录真实传递。命中、重复条数不是成功率、节省调用或有效记忆数。

最终全量回归：Windows / Python 3.12.14，458 项测试，451 通过、7 项跳过，0 失败、0 错误，105.992 秒。跳过项为 5 个 POSIX/Linux 专属用例及 2 个缺少 Windows 符号链接创建权限的用例；不能冒称 Linux 集成验证。

离线回归覆盖重复聚合、相反条件、多前提、安全路径、跨分支、来源绑定、错误可选字段、提示预算、实际执行动作改变、反馈传递及原交付/预算链路。脚本化策略测试使用真实文件和命令，但不是 DeepSeek 效果实验，也不证明 SWE-bench 成功率提升。完整计数与实现哈希见 `VALIDATION_V8.json`。

仍沿用 `off / legacy / conditioned` 小规模开发编排，默认仅预览，最多 10 题，显式执行才调用模型。三臂比较的是完整经验机制组合；不能据此单独声称某一种匹配算法有效。原 `cli-comparison-v1` 冗余率仍是重复代理，不是“所有语义无效调用”的精确度量。误拦率、因果节省调用和官方结果没有测得时继续为 null。
