# v7：让任务内试错证据改变后续决策

日期：2026-09-21。基线为 `../delivery-hardening-v6` 的独立副本；原 v6/v5、云端代码、题单、历史结果不变。本次只执行离线回归，不调用 DeepSeek、不启动付费实验、不读取参考补丁或隐藏测试。

## 修改范围

默认 `--experience-mode conditioned`，另外提供 `off` 和 `legacy`。三种模式共用模型/工具调用通路、基础搜索骨架、候选与交付、统一研究指标。

- `off`：不检索/干预额外经验；保留正常结构化上下文、任务事实和搜索历史。只在后台记录同口径的观察诊断。
- `legacy`：保留旧 recommend/avoid 蒸馏、引用加分和语义覆盖剪枝，使用本版本共同的显式交付基础设施。不是旧 v5 整体复现。
- `conditioned`：每个真实转移都可记录观察，包括 `exploring`；经验的引用只是审计注释，不触发引用数量加分、recommend 独占前沿或语义方向硬封禁。off 与 conditioned 均不把语言层面的 covered 标签当作阻止必要重读的依据。

这是经验机制的组合改动；三臂结果只能比较组合，不能单独证明某个子机制的贡献。初始计划不要求先收集经验，当前证据足够时可以直接修复。

## 经验契约

`TaskExperienceStore` 每次任务运行重新建立，不读取上一题记录。观察、模型假设、可复用验证方法分开保存：

1. **实际观察**来自真实 `CommandResult`，包含命令、退出/超时/拦截状态、stdout/stderr 有界摘要、可用输出哈希、原节点/迭代、工作区和依赖。执行前的 expected_effect 不能成为已成功经验。若上游已经截断，哈希只覆盖可用的 CommandResult 输出，不冒称原进程完整输出；`output_truncated` 会明确标记。
2. **模型假设**始终标记 unverified，并引用产生它的命令证据 ID。一次修改失败仅说明该次尝试没有消除此复现，不能据此宣布某函数或整个语义方向无效。
3. **公开验证方法**只来自确实执行过的声明验证命令；旧 pass/fail 不传给新补丁。运行成功不证明测试语义充分，也不等于官方 resolved。

规则投影携带来源 ID、条件状态、依赖路径和反例建议。过长条目整体舍弃，而不是删除证据只留下强制指令。模型 `experience_revision` 可解释相对既有失败改变了什么前提，但它仍是文本声明，不是因果证据；换说法不会改变动作身份或获得加分。

## 有效性与动作干预

- 对少量直接、确定性、显式文件的只读查询解析依赖，检查文件内容和可识别的执行条件；相关文件变动解除重复拦截，无关文件变动不必让该观察整体失效。
- 未知依赖保守记录工作区状态，仅作软提示。不依据自然语言说明推断任意 shell/Python 程序是只读；未知命令、网络失败、超时、测试和混合读写宏不能仅凭过去的失败被硬禁止。
- 满足严格条件的重复只读候选可被拒绝，并向后续规划返回既有观察。显式提交和验证不会因为“读过了”被整体跳过。没有伪造执行结果或把未执行命令计为实际调用。
- 上游工具截断或经验摘要截断的输出不能用于硬拦；同样已知条件出现相冲突的观察时，也撤销硬拦资格。需要完整结果时仍允许重读。
- 不再让旧事实失效后仍残留一个 task-wide 的“不可重读”禁令。新规则从同一观察和依赖检查结果投影；语义假设永远没有程序级硬拦权限。
- 条件验证依赖有限可观测的文件、命令能力和环境摘要，不等于冻结整个 OS、动态库、网络或其他进程。条件不明时允许重试。

## 公开失败复现的延续

对同方向或明确引用的实际失败公开检查，在解释器/检查脚本等可验证条件不变时，候选动作最多自动附加 **一条**待重放检查。未知脚本、任意 shell、`python -c`、网络/缺依赖/超时等情况只给建议。

自动附加命令会更新动作身份，并使用原有工具预算、执行隔离、安全限制和真实指标记录。放不进当前宏或剩余预算时不越限、不假装执行；保留草稿并提示拆分只读复核。显式提交不能跳过当前适用的这一条记录复现。此检查是公开回归约束，不是新增 LLM 裁判，不证明隐藏测试通过。

当前自动重放只覆盖保守语法白名单和一条优先复现，并非完整测试依赖图或“所有历史失败都强制回放”；其余观察仍供模型制定验证计划。误写的公开检查也可能误导模型，不能把自选检查视为正确性 oracle。

## 诊断与公平性

正常结果和检查点包含 `experience_mode`、`experience_report`、`task_experiences`。报告保留候选干预理由、依赖失效、实际执行情况和命令证据，可以追查具体记录，而不只看经验命中率。

- 同条件失败重现：有限可观测状态下同命令失败再次出现的代理计数，不宣称因果或必然无用。
- 被拦重复候选：没有执行的候选数量，不是实际工具调用，不可直接当作节省调用量。
- 条件改变允许重试：安全性诊断，不自动等同于避免了一次误拦。
- `false_block_rate` 和 `causal_tool_calls_saved` 留为 null；需要成对继续执行/人工审计才能估计。
- 原 `cli-comparison-v1` 三主指标实现不变。原冗余率仍是同命令/可观测状态/输出重复的代理，必要复验也可能计入，不能改口称其为语义无效调用率。
- 经验提取不新增模型请求；本地解析和摘要有计算成本，自动复验照常消耗工具额度。整体 token/工具/耗时以实际记录为准，不能承诺成本必降。

## 离线验证与下一步

最终全量验证：Windows / Python 3.12.14，**409 项测试，403 通过、6 项平台条件跳过，0 失败、0 错误**，耗时 97.392 秒。跳过的是原有 5 项 POSIX/Linux 测试及 1 项符号链接权限测试，不能视为 Linux 实测。机器可读收据见 [VALIDATION_V7.json](VALIDATION_V7.json)。v6 实现指纹复核未变；裸模型实现和原统一三指标实现逐文件哈希与 v6 相同。

新增经验库、运行时、适配器和三臂编排回归。固定前缀 fixture 使用脚本策略和真实文件：首次读取完全相同；off 多执行一次换名读取，conditioned 复用证据后修复；两者均需真实公开验证后显式提交。另覆盖真实公开失败复现重放、预算不足保留草稿、引用不加分、任务隔离、失效允许重试等。

这些是工程契约测试，不是 DeepSeek 实验，不是历史 SWE 案例重跑，也不证明成功率已经提升。通用模型断点恢复未在此版实现；固定前缀测试不是生产断点续跑的承诺。

`run_experience_ablation.py` 默认只生成计划，限制 1–10 个明确选择的开发题；只有显式 `--execute` 才运行。冻结题单、三臂共同参数、实现、解释器/包元数据，使用全新输出目录、每臂一次，不静默重试或自动官方评测。所有计划任务留在汇总分母，缺失指标返回 null。详细用法见 `EXPERIENCE_EVALUATION.md`。

先用少量开发题查真实行为，再决定是否扩展实验。历史 100 题已参与诊断，应视为开发数据，不可继续当作未触碰测试集。
