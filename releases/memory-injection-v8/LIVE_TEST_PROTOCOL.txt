测试设计
- 缺文件、缺本地依赖、维度错误三类；每类有记忆/无记忆各一组，共六次运行。
- 每次先执行两次真实失败检查，作为受控初始证据；它们是脚本动作，不是模型动作。
- 之后所有下一步决定由真实模型生成，不给它预设修复路线。
- 开启记忆的一组由生产观察器自动建立失败记忆；关闭组也有相同失败历史。
- 执行器只允许 microtool list/read/copy/write/check，保护原始检查代码；不允许
  自由 shell、模型生成的 Python 代码、网络操作或修改不相关文件。
- 因此这是受控 CLI 行为实验，不是完整 LHTB/LongCLIBench，不估计总体成绩提升。

预算
- 每组最多 12 轮逻辑请求，包含前两轮脚本种子；最多 10 次真实模型决定。
- 六组总计最多 60 次真实模型决定；每次最多两次 wire 尝试，总上限 120。
- 每次输出最多 4096 tokens；每组墙钟上限 180 秒、命令上限 10 秒。
- 独立验收器每组额外执行一个固定检查，和 Agent 工具计数分开记录。
- 身份/余额错误立即结束后续组；旧输出存在则拒绝重新启动，防止重复花费。

结果要看什么
1. 真实模型请求中是否有记忆，实际 API 调用了多少次。
2. 它是否主动执行具体修改，而不是只在 review 中声称换路线。
3. 未改文件前是否继续提议相同失败检查；哪些被代码拒绝。
4. 独立检查是否验证了修复；保护的源文件是否仍未被改动。
5. 有／无记忆组各自表现，不能把 schema 合规、模型自述或程序拦截
   单独当成记忆带来的因果增益。每组只有一条样本轨迹，不做显著性结论。
