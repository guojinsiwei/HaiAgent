# BestFGS 图搜索候选版：graph-agent-v1

这是独立候选版，不覆盖旧版、实验记录或云端代码。不是把执行日志画成图，也不是记忆知识图谱；它用**真实文件快照、全局状态—动作前沿、逐边执行和条件记忆**搜索解题路线。尚未证明它优于 RAW 或现有顺序版本。

## 历史依据

- `releases/branching-memory-v13/BRANCHING_V13.md`：恢复父快照分支与全局最佳优先搜索。
- `releases/branching-memory-v14/V14_PROTOCOL.md`：记录源节点切换、合并、节点/边和独立官方评价。
- `releases/collaborative-graph-v15/V15_COLLABORATION.md`：旧三角色是行动、评估、记忆，每个动作通常需要三次模型调用。
- 本版从 `releases/recovery-counter-fix-v9` 复制当前工程基础，复用历史 `priority.phase_weights`；**重新实现轻量图控制器，不宣称逐行恢复原图算法**。不恢复旧版每步评估/记忆模型，不混入 HAI 路线控制或三维正交门控。

## 实际链路

1. 保存根文件快照。节点包含文件指纹、已观察结果、分支对话和当前状态的公开检查记录。
2. 解题模型从一个确定节点提出最多两个候选下一步。候选是兄弟动作，不是顺序脚本；每次只执行一条边。
3. 代码在全图比较“待执行边”和“可继续扩展的节点”。排序参考公开检查、实际新观察、条件记忆提示、失败代价和等待时间，不采信模型自报成功率或正交证明。
4. 选中旧节点时恢复它的文件快照、对话和证据视图，并核对指纹。模型/工具/向导/监控预算不重置。
5. 执行动作，沿用当前 ANSI 清洗、管道状态识别、原始日志、公开检查识别和任务内记忆机制。创建结果节点，保留未选中的兄弟边。
6. 相同文件并不等于相同节点：只读检查也能增加知识。仅在文件指纹、完整捕获的结果集合、最新结果与检查映射一致时合并。结果身份用压缩前的输出哈希，不用短日志片段。
7. 由模型明确提交，或因共享预算/图容量/前沿耗尽停止。全部交给外部官方评测；内部不会标记官方成功。

## 记忆与角色

- 解题模型：提出候选、做简短记忆适用性分析、决定是否提交。
- 监控器：按已有冷却和额度检查当前分支及明确标注的历史证据，生成有证据引用的条件记忆；不执行命令、不判官方成功。
- 向导：接收已有交接报告，提供具体假设和检查建议；不绕过额度或预算。
- 记忆：单题共享，保留条件、目标文件、执行时依赖指纹及证据。跨分支提取时仍检查适用性；不同分支的经验不会自动变成当前事实。
- 对话和热证据：分支局部；预算、ID、记忆库及审计：任务全局。
- 记忆仍放在最终请求末尾保护区。每个候选动作分别使用原有结构化记忆分析字段，不要求长篇推理过程。
- 排队候选如果可见记忆 ID 集合发生变化，会被标为过期并重新提案，不误算为模型协议错误。重新提案仍占原有扩展与模型预算。

角色是独立客户端，默认可用同一模型权重；不代表必须用三个不同大模型。只有节点扩展、实际监控和实际向导调用才产生模型请求。全局队列选边和复用旧结果不调用模型，执行/恢复仍有真实计算与磁盘开销。

## 范围与限制

- 快照只恢复工作区文件，不恢复进程、网络服务、数据库服务、系统安装包或工作区外文件。因此目前定位是一次性隔离环境里的文件型 CLI 任务。系统级依赖变更不能冒充已经隔离的分支状态。
- `LiveWorkspace` 要求 Linux/WSL 和一次性沙箱。相对路径检查不是安全沙箱；不要把有私密文件或重要服务的机器直接交给它。
- 工具输出不完整时不据此确认公开检查通过；新输出、文件改变和退出码零不等于任务完成。
- 当前公开检查识别仍是保守的显式 pytest 摘要，不能泛化为任意编译/自定义验证器的完整正确性判断。
- 前沿排序是可审计的启发式，不是训练后的价值函数，也不是完整恢复旧版语义地图覆盖算法。
- 非明确提交退出时，保底可选择同状态公开检查通过数量更多的已保存节点；这只是启发式，不同测试集合不保证可比。所有分支仍保留供外部检查，不能据此宣称最终质量最好。
- 默认候选宽度 2，每节点最多扩展 2 次；最多 64 节点、64 快照、64 待执行边、1200 次队列选择。图容量是额外、显式的资源限制，可能早于 600 工具调用耗尽；正式对照必须记录并统一解释预算。
- 文件快照会占用磁盘和复制时间。本版没有自动清理用户工作区或历史实验。
- 没有加入之前讨论的清缓存、诊断随机参数、无限向导救援或重复两次后的强制改环境规则。
- 没有部署到云端、没有修改现有实验启动器、没有消耗真实模型 API。

## 入口与验证

在本目录运行 `python verify_graph.py`，执行已有回归及新增图搜索专项测试。结果写入 `offline-acceptance.json`。脚本化客户端不调用真实模型 API。

真实执行使用独立入口，需先在 Linux 一次性沙箱内完成环境验收，并由用户安全提供自己的 API 环境变量：

```bash
python run_graph.py \
  --workspace /sandbox/task-seed \
  --run-root /sandbox/runs/graph-trial-unique \
  --goal '任务原文' --task-id trial \
  --provider deepseek --model deepseek-flash \
  --api-key-env EXPERIMENT_API_KEY \
  --max-tools 600 --max-turns 800 --wall-seconds 3600
```

`run-root` 必须是不存在且与任务种子不重叠的新目录。此命令会调用模型；本次只验证了 `--help`，没有执行它。真实 Linux 执行器、云端 benchmark 适配及模型效果仍待验收，Windows 文件快照测试不能替代它们。

输出 `audit/search-graph.json`、完整事件/最终请求审计、条件记忆与 `result.json`。搜索边注明来源、去向、状态、证据和排序分解，可直接查是否真的分叉、回退、合并，而不是只看节点数量。

主要代码：`graph_search.py` 管数据结构与排序；`graph_runtime.py` 管全局调度、分支执行与接线；`graph_cli.py` 管显式入口。旧 `lean_runtime.py` 的顺序入口仍保留，原行为由回归测试保护。
