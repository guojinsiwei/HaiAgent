# v16：把终端小组件的两个功能接入三角色 BestFGS

源版本为 v15，多模型分工不变。这次只改变模型输入视图，不改变搜索、执行、提交或评测。
未部署、未调用付费模型。旧 v15 和 HAIAgent/独立组件没有修改。

## 1. 硬编码常见工具输出压缩

| 命令类别 | 模型视图策略 |
|---|---|
| pytest、python -m pytest/unittest、npm/cargo/go test | 优先保留失败/异常、周边行及末尾汇总 |
| make、cmake、ninja、gcc/g++、cargo | 优先编译错误、警告、结尾诊断 |
| pip、python -m pip、npm、uv | 优先依赖冲突、安装错误与尾部信息 |
| ls、find、tree、git status | 有界、带原输出行号的列表片段 |
| rg、grep | 保留原匹配行文本和已有路径/行号，不把省略解释为没有匹配 |
| git diff | 优先文件和 hunk 标识，再保留片段；不是可应用的完整补丁 |
| cat、sed、head、tail；无法识别的命令 | 保守头尾截取，不做语义改写 |

短输出原样保留。简单 `bash -lc 'pytest -q'` 可识别；包含管道、重定向、连接符、
变量替换、命令替换、换行或嵌套 shell 的命令回退为通用策略。不执行或改写命令。

压缩基于确定性规则，零额外 LLM 调用。输出包含源 channel/index、原退出码、超时/
阻止/采集截断状态、捕获内容长度与 SHA-256、压缩策略版本及显示截断标志。
行号指**捕获输出的行号**，不是凭空推断的源文件行号。
显示截断和环境采集截断分别记录。原 ExecutionOutcome/检查点中的已捕获记录不改写；
环境原本可能有输出上限，因此不声称保留无限完整 stdout。哈希也仅针对捕获内容。

多个结果保留原证据索引，各 stdout/stderr 按非空需求分配预算，错误流及失败结果优先，
空流不占额度、短流多余额度回流给其他输出；按 JSON 转义后的字符数检查
`max_observation_chars`（默认 8,000），不是把每个输出各放大到 8,000。若小到连源身份
元数据都装不下，明确报错，不悄悄删除来源。特别大的输出保守头尾截取，避免无限扫描。

压缩不能保证每条关键诊断都入选；省略标志提醒模型针对需要的文件/范围再次检查。
不生成“测试已成功”或“无错误”判断，原验证门控仍读取真实结果。

## 2. 独立记忆提示区

每次策略请求的动态部分包含 `[TASK_MEMORY_BEGIN]` / `[TASK_MEMORY_END]` 区块。
它不是更高权限的 system 指令，也不是跨任务记忆，而是有独立额度的数据区。

- 默认从原 14,000 字符结构化上下文预算中预留 2,500；普通视图最多 11,500。
  两份 JSON 有界，区块标签和其他提示词固定文字另计；这是字符预算，不是 token 上限。
- 行动角色优先放入**原检索器已经选出的规则**，不新增检索算法、不生成更多碎片。
  保留规则 ID、条件、适用状态、来源及失效信息；超预算整条省略，记录数量。
- 剩余额度放近期、有观测支持的结构化事实，保留来源和 `verified_at_observation`。
  历史验证不等于当前仍有效，明确要求重新判断状态和条件。
  事实同时保留已有的 workspace_dependencies 和 observed_at_fingerprint，不补造依赖。
- 评估/记忆角色用真实转移的父上下文重建记忆区；它们原接口没有召回规则，因此不从
  上一次行动调用偷带规则。三者都不把上一个分支的隐藏缓冲区当当前记忆。
- 普通上下文变长不会吞掉记忆预留区。极端方向数超限只删**显示记录**并标记数量，
  不删搜索图节点、完整上下文或记忆库；旧事实失效/准入机制保持原样。
- experience_mode=off 不放额外规则或事实，保留明确的禁用标识。

目前事实优先级只用已有验证标签和近期顺序；不是新学到的“重要性模型”。当前没有
增加记忆自动执行、重复行为拦截、长期跨任务记忆或完整原始日志无限存储。

## 控制与审计

v16 图协作入口默认启用，可关闭压缩与记忆区，恢复旧展示方式（0.16.1 的防遗忘更新仍保留）：

```powershell
$env:BESTFGS_TERMINAL_VIEWS = 'off' # 默认 on
```

模型用量中记录 `prompt_view_policy`，模型角色配置方式仍见 `V15_COLLABORATION.md`。
`prompt_views` 另记视图构建次数、最近 32 个视图的哈希、长度、实际显示规则 ID 和省略数，
不额外缓存正文。原规则检索/暴露诊断计数不能自动当作新视图的实际显示数；本次不改指标定义。
独立的原 `RetracPolicyAdapter` 默认保持旧视图；Raw/evidence 引擎不变。
每次工具执行后的评估和记忆模型各调用一次，不因压缩增加调用。
成本、成功率或循环改善尚未实测。正式对照需冻结新版本，不能混入旧 v15 结果。
