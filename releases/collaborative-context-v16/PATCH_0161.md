# 0.16.1：只修复上下文覆盖与输出额度分配

## 未提及不删除

协作策略将 `unresolved_issues`、`incomplete_plans`、`analysis_and_conclusions`
视为增量列表：程序保留完整父上下文中的旧项，加入新项并按原文去重。
模型返回 [] 表示没有新增；即使压缩提示词没有显示旧项，也不会清空它。

更新/删除旧项须由记忆角色返回 `context_changes`，明确字段、旧项原文、
resolved/invalidated 状态、结果 channel/index、原文引用与原因。最多 12 条。
程序检查项是否存在、结果引用有效、引文确实出现在对应 stdout/stderr，且结果未超时、
被阻止或发生采集截断。不合格时仅重试记忆角色，不重复执行工具或评估模型。
有效更新的动作 ID、结果来源、引文和原因进入结构化结论，便于检查点追溯。

引用匹配不等于证明因果推断正确：是否真的解决问题仍包含模型判断，不能当官方成功。
被显示截断的长旧项若无法准确引用，保守保留，不模糊匹配删除。
历史事实有效性、工作区变更失效、方向合并仍交给原图运行时；没有无条件复活旧事实。
不额外开模型总结调用，也不擅自扩大预算。

## 输出额度不再平分浪费

先保留所有来源元数据，再按各非空流的实际 JSON 字符需求分配剩余额度。
stderr 和失败/超时/阻止结果的输出权重为正常 stdout 的三倍；空流分零，
短流达到实际长度后将额度让给其他流。总 JSON 仍受原 max_observation_chars 限制。
原命令感知压缩、截断说明和原始捕获记录保持不变。
