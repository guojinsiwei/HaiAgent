# BestFGS 多角色协作图搜索候选版 v2

本目录是独立可读、可测试的候选源码，基于 `graph-agent-v1`。不覆盖旧版本，不修改云端实验。它结合真实状态—动作图、单题条件记忆和按需协作；目前已做离线验证，尚未验证真实模型表现。

## 谁负责什么

| 组成 | 职责 | 权限边界 |
| --- | --- | --- |
| 解题模型 Actor | 看当前分支证据与记忆，提出最多两个兄弟候选；采用、调整或拒绝建议；决定提交 | 只能提出动作，不能自行恢复图节点或修改预算 |
| 监控器 Monitor | 检查刚执行完的分支，判断进展/停滞，提取带原文证据的条件记忆 | 判断可能有错，不判官方成功，不执行命令 |
| 向导 Advisor | 根据交接报告，提出最多两个解释、区分性检查和可选的预期输出 | 建议不会自动执行，不绕过预算或冷却 |
| 图调度器（程序） | 在全图选择候选或扩展节点，恢复来源快照，合并等价状态，记录实际反馈 | 只用公开观察；启发式优先级不等于任务得分 |

三个角色使用独立客户端，默认模型相同，也可以给监控器、向导分别配置较小模型。普通动作不要求三个角色各调用一次；监控与向导按需介入。

## 实际协作过程

1. Actor 根据当前节点提出具体候选。节点含文件快照、观察集合、分支对话和同状态公开检查结果。
2. 图调度器从全局候选中选一条，恢复其来源节点后执行。未选的兄弟候选保留。
3. 在切换分支之前，Monitor 检查刚得到的结果，避免恢复别的分支后才去评估、漏掉失败现场。
4. 如果需要帮助，Advisor 接收目标、卡点、历史尝试和证据编号，提出假设与检查建议。可选 `probe` 和 `prediction` 给出具体命令以及支持/反驳假设的短输出标记。
5. Actor 可附简短 `advice_review`，说明采用、调整或拒绝。字段不合格只记录为未关联，不增加致命协议错误。
6. 程序对比实际命令与建议，并核对执行后的输出。分别记录新证据、工作区变化、同一个公开检查是否改善；缓存旧结果不会算成一次新的验证。

这里的“预测核对”是**字面输出标记核对**，不是另一个 LLM 裁判。匹配代表观察到了标记，不代表假设因果成立、建议有效或任务成功。记录缺失、动作改变、输出不完整或支持/反驳同时出现时，保留无法比较/未知状态。

图排序中，同节点停滞评审为 `-0.12` 的软调整，命中向导具体检查且未拒绝为 `+0.08`。数值尚未调优；不产生硬性路线封禁。继承的排序还参考公开检查、新观察、条件记忆、失败代价和等待时间。

## 近期经验落实在哪里

- **减少无效门控**：不加三维正交证明，不因向导建议格式错误提前终止解题；一个坏建议不会丢掉另一个合格建议。
- **证据与自述分开**：提出、采用声明、实际执行、缓存返回、观察匹配分开审计，不能靠“我换了策略”就计为有效改进。
- **记忆有适用条件**：单题共享，保留文件/依赖指纹、证据与状态；对话与当前证据按分支隔离，历史经验不能冒充当前事实。
- **记忆内容变更也使旧提案过期**：检查可见记忆 ID 和内容摘要。同一 ID 的内容更新后，排队提案须重新读取，不误算协议错误。
- **保护上下文**：沿用末尾记忆保护区、完整请求审计、监控紧凑上下文与交接报告。模型只需简短事实摘要，无需长篇推理。
- **工具反馈可信度**：沿用 ANSI 清洗、原始输出保留、管道状态与命令/公开检查分离；不完整捕获不能确认检查通过。
- **重复与恢复**：沿用状态相关命令规范化排重和恢复计数修复；相同条件旧结果可复用。没有添加强制清缓存、随机参数或无限次向导调用。
- **控制动作身份修复**：咨询、提交、历史检索分别去重，历史分页包含 offset；它们不会再因为没有 argv 而被当成同一个动作。
- **交付不能比较无关测试数量**：非主动提交退出时，只有公开检查集合相同且通过集合严格增加，才会回选另一节点。主动提交不会被覆盖。
- **预算统一**：所有分支及 Actor/Monitor/Advisor 共用模型请求、工具和时间预算，恢复不重置；各辅助角色另有额度与冷却。底层网络重试单独审计。

## 建议从这几个文件开始读

源码在 `sources/bestfgs-project/src/bestfgs/`：

1. `graph_collaboration.py`：这次的主要新增，角色交接、建议与动作关联、输出核对、协作审计。
2. `graph_runtime.py`：真实图调度循环、父状态恢复、逐边执行、合并、共享预算。
3. `graph_search.py`：节点/边、候选协议、可解释的启发式排序。
4. `graph_roles.py` 与 `graph_cli.py`：独立角色模型配置和启动入口。
5. `lean_runtime.py`、`lean_monitor.py`、`lean_memory.py`：复用的执行、监控、记忆基础。

专项测试在 `tests/test_graph_collaboration.py`；基础图测试在 `tests/test_graph_agent.py`。

## 离线验证与运行入口

在本目录运行：

```bash
python verify_graph.py
python run_graph.py --help
```

离线用脚本化模型、文件快照夹具，不读取真实 API 密钥，不调用真实模型。本轮在 Windows / Python 3.12 上 **166 项通过，0 失败、0 错误、0 跳过**，其中 18 项为本版新增协作测试；机器可读结果见 `offline-acceptance.json`。

真实运行必须先在 **Linux 一次性隔离环境**完成执行器验收，并安全配置自己的 API 环境变量。下面是待验收的启动方式，本次没有执行：

```bash
python run_graph.py \
  --workspace /sandbox/task-seed \
  --run-root /sandbox/runs/collaborative-trial-unique \
  --goal '任务原文' --task-id trial \
  --provider deepseek --model deepseek-flash \
  --api-key-env EXPERIMENT_API_KEY \
  --max-tools 600 --max-turns 800 --wall-seconds 3600 \
  --advisor-calls 6 --monitor-calls 12
```

`run-root` 必须尚不存在，且不能与种子工作区重叠。`--advisor-model`、`--monitor-model` 可分别指定角色模型；换 endpoint/provider 时必须同时显式指定模型与该角色的 `--*-api-key-env`，不会默默把原端点的密钥发送过去。工具进程会移除这些已配置的凭据环境变量，但这不能代替系统安全隔离。

`--no-cooperation` 切回普通图调度角色接线，关闭本版协作关联、软优先级及预测核对；监控/记忆默认仍开。它是组合开关，不是单一因素消融，也不等于 RAW。CLI 未接入已有 benchmark 启动器。

## 看哪些产物

- `audit/search-graph.json`：节点、边、来源、去向、排序分解及执行/缓存/过期状态。
- `audit/collaboration.json`：监控评审、向导建议、候选关联与执行后核对。
- `audit/events.jsonl`：具体过程及最终请求审计。
- `audit/memories.json`、`audit/result.json`：条件记忆与共享预算/停止原因。

看效果应追踪“建议出现 → Actor 是否看到 → 实际动作是否对应 → 有无新证据/同项检查改善”。单看建议条数、记忆条数或预测标记匹配数不能证明收益。

## 验证边界

快照只恢复工作区文件，不恢复进程、网络、系统依赖、外部数据库或工作区外文件。跨节点的这类外部状态不保证一致。公开检查识别目前主要依赖明确的 pytest 摘要，并非通用评分器。

默认宽度 2、每节点最多扩展 2 次、64 节点/快照/待执行边、1200 次调度选择；这些上限可能先于工具预算耗尽，必须报告实际停止原因。仅文件快照和离线角色契约通过，不能宣称 Linux 生产执行器、LongCLIBench 接入或真实解题质量已验收。

本次未部署、未启动实验、未消耗真实模型 API；旧版本、历史结果和现有任务保持不变。
