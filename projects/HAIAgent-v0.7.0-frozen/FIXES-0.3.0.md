# 0.3.0：行动协议修复

## 已确认与不能确认的原因

2026-09-26 学院节点的 path-tracing HAI 运行暂停时，54 次回复中有 38 次 JSON 解析错误，大量报错为 `Extra data`。HTTP 请求获得正常信封，提供方返回模型为 deepseek-flash、finish_reason 为 stop。这说明应用层读到了一个 JSON 值之后的额外内容，不是一般连接失败或单纯输出截断。

旧日志没有保存被拒绝的回复，只保存了解析错误，所以无法事后断言额外内容一定是第二个行动、经验对象还是解释文字。没有据此伪造“真实响应回放”或宣称查明了提供方的内部原因。

代码层确定存在的设计缺口：依赖正文 JSON 传递行动；格式失败后只给通用重试提醒；没有专门熔断；没有足够的失败响应诊断。

## 修改

1. 默认用原生单一函数 `choose_action`，从 `tool_calls[].function.arguments` 读取行动。附带正文不作为可执行行动。
2. 强制指定该工具，但仍本地检查必须只有一个调用、正确工具名和真实 call ID。多个调用、拼接 JSON、重复字段、数组、非有限数、截断响应均不执行。不偷偷取第一个行动。
3. 正常历史保存实际 provider call ID 与对应 tool 结果；预算压缩时转成明确的历史摘要，不伪造 native tool calls。
4. 连续 3 次或累计 8 次格式错误停止本题，stop_reason=protocol_error，退出码 6；不额外调用修复模型，不自动重跑。
5. 错误日志记录先脱敏再截取的有界片段、摘要、长度和结构分类，便于下次确诊。
6. HAI 与 Raw 使用相同传输、计数和熔断规则。Raw 的工具 schema 不含记忆字段。

## 提供方与实验边界

DeepSeek 官方文档说明指定 tool_choice 在 thinking 模式不可用，因此官方端点明确请求 thinking=disabled；没有隐式切换 beta 端点或开启 strict 模式。这是需要重新冻结的配置，不能假定旧试验的未显式声明模式与新试验完全相同。

- 官方工具调用文档：https://api-docs.deepseek.com/guides/tool_calls/
- 官方参数文档：https://api-docs.deepseek.com/api/create-chat-completion/

项目版本 0.3.0，运行协议 hai-v3；成功率、轮次、语境工具调用冗余率公式不变。旧云端实验保持暂停、源码和记录不覆盖。没有恢复旧轨迹，没有启动新一批付费任务。

离线回归验证的是实现，不证明真实 DeepSeek 端点每次都会遵守格式。下一步应先用新凭据做少量真实协议验收，确认后才重启配对实验；真实响应也会计费，不能冒称已验证。
