# 0.4.1：工具调用兼容层与可审计错误分类

## 真实故障

LongCLI Cats 的提供方请求成功并返回 `finish_reason=tool_calls`，但工具调用封装连续三次未通过旧版一体化校验，任务在约 19 秒后以 `protocol_error` 结束。旧日志只留下 `Invalid tool identity/arguments`，随后又被误标为 `malformed_json`，无法区分工具类型、名称、call ID 或参数载体错误。

## 修复范围

- 对不改变动作对象语义的提供方偏差做显式规范化：缺失 `type` 视为 `function`；缺失、非字符串或超长 call ID 替换为基于参数摘要的确定性本地 ID；参数若已是 JSON 对象则确定性序列化为 JSON 文本。
- 错误工具名、非 `function` 类型、多/零工具调用、非字符串且非对象的参数、超大参数仍然拒绝。不会选取多调用中的第一条，不会从正文猜动作，也不新增隐藏模型修复调用。
- 每次规范化记录 `tool_call_normalized`；失败记录具体分类，例如 `tool_call_wrong_name`、`tool_call_wrong_type`。审计只包含字段类型、长度、名称、摘要和规范化项目，不保存参数原文。
- `response_diagnostic` 优先保留工具传输分类，不再把空正文下的工具封装错误误报为 `malformed_json`。

## 实验边界

这是基础设施协议变化，源码和协议摘要会改变。旧实验保持冻结，0.4.1 结果不得与 0.4.0 或更早轨迹伪装成同一协议续跑。Raw 与 HAI 必须使用同一兼容层。该修复不改变 Agent 策略、记忆、题单、轮次/工具预算或科研指标定义。

离线回归包含：无 `type`、无 ID、对象参数的联合兼容；错误工具类型与名称继续拒绝；诊断不泄露参数原文；多调用仍不执行。
