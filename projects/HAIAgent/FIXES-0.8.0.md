# HAIAgent 0.8.0

本版修复 0.7 实验暴露的核心缺口：记忆虽然能生成，却没有稳定进入真实动作选择闭环；只换临时文件名即可绕过精确重复检测。

## 决策闭环

- 每次请求用任务、最新命令/错误、当前方向、策略和子目标生成动态召回查询，不再固定只查题面前 500 字。
- 主机从实际动作构造有界语义方向：解开常见 shell 包装，保留工具链、工作区目标和有限稳定参数，只消除临时脚本名等偶然差异。
- 三次同方向、等价反馈且无工作区变化时自动保存带证据的停滞记忆；这只是观察，不声称该方向永远无效。
- 下一条匹配动作执行前固定展示相关记忆并暂停执行。模型可以换方向、检查适用性，或用 `uses_memory` 明确引用后有限继续。
- 同一方向默认只允许一次记忆覆盖；改临时文件名或反复引用同一 ID 不能无限绕过。具体 `retry_reason` 仍使用独立的有限解释性重试预算。
- 失败记忆不再因共享目标文件而拦截完全不同的方法；只有同方向失败或显式目标约束会触发执行前干预。

## 上下文与交付

- 固定区新增 `semantic_directions` 与 `memory_intervention`，相关记忆优先于普通召回且仍受总字节预算约束。
- 保护区显示显式请求路径存在性及轻量预算阶段。两者都不判断正确性、不调用额外模型，也不强制提交。
- 保留模型自主提交、单路径执行、无内部成功评分的设计；没有把 BestFGS 分支或 advisor 引入 HAI。

## 审计

- 记录 `memory_intervention`、`memory_reconsideration`、`memory_use_self_report`、`memory_override_exhausted` 与 `memory_followup_outcome`。
- 区分“动作文本改变”和“语义方向改变”；机制利用率只描述关联，不作为因果收益或官方成功。
- Raw 的提示、行动字段和运行逻辑不启用上述 HAI 上下文与拦截。

## 验证边界

离线测试覆盖改写 `/tmp/opt199.py → opt200.py` 的空转、不同 Bash 工具不误合并、临时路径反馈规范化、干预后换方向、一次明确覆盖及第二次覆盖被拒、合理解释性轮询、预算交付提示和 Raw 不干预。离线通过只说明工程契约成立；真实性能仍需新协议哈希下的独立 benchmark 对照实验。
