# v14 基础设施取舍

来源：原工程 `releases/branching-memory-v14`。本工程不引用该目录运行，桌面副本可单独迁移。

## 保留并适配

- `submission.py` 的固定 Git 基线、临时 index/object store 和累计补丁导出逻辑；避免遗漏新增/暂存文件、不修改用户真实 index。增加共享墙钟期限、过滤控制器环境变量，去掉无关旧目录排除。文件中保留可选的独立交付物重建工具，但默认提交不会强制调用它。
- `retrac_adapter.py` 用独立进程约束 HTTP 绝对时长的设计，重新实现精简的非流式 Chat Completions 客户端。没有照搬大型策略适配器、思维框架或其依赖数据类型。
- `environment.py` 的 argv/shell=False、cwd 范围检查、超时结果、控制器凭据隔离思路；改为单工作区、有界流捕获与进程树终止，不继承每步 fork/copy 结构。
- `experiment_metrics.py` 的执行边界记账、新运行拒绝覆盖和运行证据思想；指标定义与实现重新编写，不导入旧冗余检测器。
- 先前新建的 `components/terminal-context` 以独立包副本内置，保留其测试。`hai` 模式每轮真实接入，`raw` 模式关闭，不使用 v14 经验/阻塞模块。

## 不继承

Best-first 搜索、强制分支扩展、候选评分、覆盖率奖励、隐式模型成功裁判、RL 更新、阻塞替代执行、语法门禁、提交时强制审查与复测、额外 LLM 反思/总结、自动无限重启、历史机械重复率。

原因：这次研究对象是轻量上下文与任务内经验是否能帮助单路径模型决策。把旧框架全搬过来会重新混入额外调用、状态切换和终止策略等变量，无法清晰归因。

## 版本边界

这是 HAIAgent v0.1 的新协议，不是“v14 改了个名字”，也不能把本工程的 Raw 与历史旧 Raw 数值直接比较。它有新的动作单位、提交策略和指标审计口径。正式实验应在新工程内冻结同一配置，分别运行 `hai` 与 `raw`。

不复制模型 Key、旧实验日志、缓存、数据集、Docker 镜像或云端部署脚本。离线验证使用临时合成任务，不消耗 API 额度，不改变已部署实验。
